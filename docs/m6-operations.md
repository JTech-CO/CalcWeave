# 로컬 베타 운영·복구 절차

2026-10-03 · 운영자 JTech-Co · 문의 jtech-bryan@proton.me

## 관측과 자료 최소화

관리 화면에서 저장소 사용·할당량(브라우저가 제공한 경우), 백업 알림 시각과 최대50개 로컬 진단 기록을 확인한다. 기록은 고정 오류 코드·문맥·시각·엔진 버전만 포함한다. 메시지·스택·모델/데이터 내용·파일명·URL·연락처는 기록하지 않는다. 기록 내려받기는 사용자 동작이며 자동 전송이나 운영자 원격 조회는 없다. 마케팅/분석 SDK, 쿠키 배너를 필요로 하는 선택적 추적과 서버 접속기록 수집 코드는 없다.

온라인 정적 파일 요청은 예정 호스팅 GitHub Pages와 통신한다. 호스팅 플랫폼이 처리하는 접속 정보와 운영자 접근 가능 범위는 공개 전에 확인한다. 원격 오류 전송·비용/장애 알림 서비스를 묵시적으로 추가하지 않는다. 공개 후 상태 확인은 `npm run verify:deployment`로 HTTPS·현재 버전·정책·SW·보안 헤더를 읽어 수행하며 운영 알림 담당과 대응 시간을 별도로 확정한다.

## 백업과 저장 실패

중요한 변경을 마칠 때 관리 → 작업 공간 백업으로 독립 파일을 보관한다. 모델 JSON 다운로드와 달리 백업은 포함 데이터·서브시스템·주석·대시보드와 최근5개 실행을 함께 저장한다. 백업 checksum은 훼손 검출용이며 출처 인증이나 암호화가 아니다. 파일에는 사용자 자료가 포함되므로 공유·보관 접근권한은 사용자가 관리한다.

저장 공간 부족·차단·충돌이면 현재 작업을 백업하고 기존 저장본을 유지한다. 다른 탭 변경 안내가 보이면 현재 탭의 미저장 작업부터 백업한 뒤 새로고침한다. 손상·미래 버전 모델은 관리 화면의 복구 원본 다운로드와 이전 정상 저장본을 확인한다. 복구 파일은 검증된 경우에만 단일 IndexedDB transaction으로 교체한다. 잘못된 백업·해시 불일치·transaction 실패는 기존 저장본을 변경하지 않는다.

IndexedDB와 localStorage 사이에는 하나의 transaction이 없으므로 전체 초기화 도중 설정 삭제 실패가 발생할 수 있다. UI가 실패를 표시하면 초기화를 다시 시도한다. 초기화는 이미 내려받은 파일·다른 브라우저/기기의 자료·오프라인 정적 캐시를 지우지 않는다. 앱 캐시까지 회수하려면 먼저 백업하고 모든 탭을 닫은 뒤 브라우저의 사이트 저장소를 정리한다.

## 업데이트 실패와 배포 롤백

대기 중인 업데이트는 저장 성공 후 사용자 선택으로 적용한다. 정적 파일 누락·해시 불일치·차단은 새 릴리스의 설치를 중단하고 기존 오프라인 버전과 작업 자료를 유지한다. 자동 skipWaiting 또는 엔진만 갱신하지 않는다. 이전 탭의 lazy 코드 로드를 보장하려고 이전 릴리스 캐시는 남으며, 디스크 사용을 무기한 작게 유지한다고 주장하지 않는다.

공개 배포 실패는 GitHub Actions의 verify/deploy job과 Pages deployment status를 확인한다. 이전 검증 commit에서 수동 workflow를 다시 실행하여 전체 앱·Worker·export asset set을 함께 게시한다. 사용자 모델은 rollback하지 않는다. 실제 이전 엔진이 최신 모델 schema를 해석하지 못하면 원본을 유지하고 다운로드·복구로 안내한다. 게시 후 domain/HTTPS, 새 allowlist와 모든 static assets, offline reload와 backup roundtrip을 다시 확인한다. 배포 이력 commit·releaseId·검증 결과를 기록한다.

## 사고 대응

의심되는 입력·오류에 대해 사용자가 제공하기로 선택한 sanitized 진단 기록과 앱 버전을 먼저 확인한다. 원본 모델이나 개인정보 제출을 기본 요구하지 않는다. 시크릿 또는 개인 자료가 공개 파일에 들어가면 해당 게시물 제거, 접근 범위 확인, 해당 키 폐기/재발급, 영향 조사와 적용 법령에 따른 통지·신고 여부를 검토한다. 운영자 GitHub 계정의 접근권한·2FA·복구 담당·호스팅 통신 처리방침은 공개 출시 전에 확인할 운영 항목이다.

## 실제 사용성 관찰 F06

처음 사용하는 참여자에게 (1) 예제 실행 (2) 값 수정 (3) 오류 위치 확인·수정 (4) 검색·연결 (5) 백업·복구 (6) TypeScript export를 설명 없이 요청한다. 완료 여부·걸린 시간·막힌 지점·도움 횟수만 동의를 받은 최소 기록으로 수집하고 개인 자료를 요구하지 않는다. 자동 브라우저 journey는 회귀 evidence이며 실제 참여자 관찰이 아니다. M0~M4의 미완료 외부/사용자 승인 gate와 실제 공개 주소 gate도 별도로 유지한다.
