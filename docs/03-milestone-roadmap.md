# CalcWeave 마일스톤별 구축 방향

> 버전: v0.10 · 작성일: 2026-10-03 · 상태: 현재144 registry·M8~M16 전체 원자료 후속 계획, M6 공개 출시 게이트 별도
> 대상 브랜드: **CalcWeave** · 예정 공개 도메인: **CalcWeave.com**  
> 도메인 등록·소유권·상표 사용 가능 여부는 별도 확인 항목이며, 현재 확보 완료로 간주하지 않는다.

관련 문서: [기술 백서](01-technical-whitepaper.md) · [디자인 백서](02-design-whitepaper.md) · [블럭 대응표](block-coverage.md) · [원본 데이터셋](../dataset/Simulink_Basic_Blocks_R2024b.md)

사용자 선택에 따라 M7 이후 확장은 수학·신호부터 진행했다.0.8.0은74→144종과27→32예제/6카테고리, toolbar 문자 표시 정리를 포함한다. 원자료 승인20행(신규19·기존Divide 추적교정1)을 추가하며 미구현251행은 후속 범위다. 모든 원본 블럭300여종의 동등 구현 완료로 기록하지 않는다. 원자료·registry·공유 커널·프리셋을 구분하고 실제 계산/생성 코드 oracle를 승인 조건으로 사용한다. [확장 계획](block-expansion-plan.md)·[계약](catalog-contract.md)·[검증](catalog-validation.md)에 진행 결과를 기록한다. 다음 수치/신호 확장은 새 실행 의미·사건 처리·타입 계약과 독립 fixture를 정한 뒤 추가하며 공개 출시 확인은 기존 M6 조건을 따른다.

앱0.8.1의 [Pages 웹 베타](https://jtech-co.github.io/CalcWeave/) 배포와 실제 공개 주소 검사는 통과했다. [배포 검증](pages-validation.md)을 참고하며 이 결과로 기존 M6의 실제 초보자 조사·목표 도메인·문의 운영 정책까지 완료 처리하지 않는다.

## 1. 로드맵이 만드는 결과

현재 catalog 이후의 전체 대응 방향은 [05. Simulink 기본 라이브러리 전체 대응 후속 로드맵](05-simulink-coverage-roadmap.md)에 이어진다. [기계 판독 배정표](simulink-coverage-roadmap.json)는 원본385행 모두의 현재 상태, 최초 작업 단계, 남은 옵션/타깃 검증과 M16 종료 gate를 기록한다. 현재144 registry와 원자료385행/339개 이름 문자열, 기존subset134행/미구현251행을 별도 지표로 유지한다. 아래 M0~M7 설명과 기간은 기존 단계의 설계·구현 기록이며 후속 단계의 확정 일정이 아니다.

### 현재 catalog 이후의 M8~M16 계획

M8 수학·신호/배열의 잔여 기능 → M9 DSP·이산 상태/샘플시간 → M10 자료형·complex/fixed/n-D → M11 조건·반복·메시지·계층 → M12 solver/사건/DAE·분석과 M13 IO/Dashboard/문자열·데이터 → M14 외부 adapter/권리/환경 gate → M15 interop·추가 target → M16 전체385행 옵션별 QA 순으로 확장한다. 필요한 선행 계약이 승인된 기능 묶음부터 진행하며 solver와 데이터/UI 일부는 병행할 수 있다.

이미 구현한134subset도 전체 옵션 지원으로 간주하지 않는다. 각 원본행의 R2024b 파라미터·자료형·shape·시간·mode·target inventory와 독립 fixture를 후속 단계에 배정한다. canonical 재사용·preset·독립 목적 대체·조건부 adapter·legacy를 구분하며, 추적 결정 완료와 검증된 실행/전체 옵션 동등성은 서로 다른 지표다. 원자료 이름·조건·현재 승인 상태는 이 계획으로 변경하지 않는다. 외부 환경·권리·수치 증거가 없는 항목은 명시 미지원으로 남긴다.

후속 문서에는 단계별 계약·fixture·종료 조건·의존·우선도와385행/251미구현 누락0 검사를 포함했다. M15/M16은 여러 기능의 타깃 검증·최종 QA이므로 최초 기능 배정0행이어도 후속 작업이 있다. Block Support Table의 최초 작업은 M13 공개 지원표, 전수 옵션의 최종 감사는 M16이다. 일정과 공개 출시 완료는 약속하지 않으며 M6 보안·운영·도메인·접근성·초보자 관찰 gate는 별도로 유지한다.

CalcWeave는 사용자가 수식과 데이터의 흐름을 블럭으로 연결하고, 결과를 확인하고, 같은 모델을 실행 가능한 코드로 가져갈 수 있는 독립 웹 제품을 목표로 한다. 제품의 진행 단위는 라이브러리 아이콘 수보다 **사용자가 완결할 수 있는 계산·실험 과정**이다. 첫 단계는 단순 수치 계산, 다음은 이산시간 시뮬레이션, 그다음은 연속시간 시뮬레이션과 반복 실험으로 확장한다.

원본 데이터셋은 R2024b 기준 21개 분류, 385개 문서 행이다. 이 숫자에는 같은 블럭의 분류 간 중복, 설정 변형, Quick Insert 별칭, 유틸리티, 조건부·레거시 항목이 포함되어 있다. **385개 독립 계산 블럭을 순서대로 구현한다는 계획으로 해석하지 않는다.** 모든 행을 대응표에서 추적하되, 실행 의미를 공유하는 항목은 하나의 canonical 기능과 사전 설정으로 묶고 의미가 다른 항목은 구분한다.

블럭 자체의 산술 계산이 단순해도 상태 갱신 순서, 샘플시간, 수치 오차, 초기값, 이벤트, 자료형, 외부 런타임의 차이를 검증해야 한다. MathWorks 도구와의 완전한 실행·파일 호환을 초기 목표로 삼지 않는다. CalcWeave의 지원 계약을 먼저 정의하고, 불가능하거나 아직 검증하지 않은 조합은 실행 전에 설명한다.

## 2. 전제와 일정 사용법

현재 작업 공간에는 M4 승인 데이터·계층·실험·독립 export 구현이 있으며, 아래 기간 추정은 제품 구현 전의 팀·범위 가정을 기준으로 한다. 아래 기간은 **수치 계산과 웹 개발 경험이 있는 전담 개발자 2명, 디자인·QA 파트타임 지원, 주당 약 30시간의 집중 개발**을 가정한 단계별 대략 범위다. 요구사항 확정, 결함 수정, 문서·fixture 작성이 포함되며, 사용자 모집·도메인 확보·인프라 계약 같은 외부 대기 시간은 제외한다.

기간은 확정 출시일이나 외주 견적이 아니다. M0에서 핵심 난이도와 개발 환경을 측정하고 다시 산정한다. 1인 개발은 단순히 날짜를 두 배로 늘려 처리하기보다 각 단계의 축소 범위를 먼저 적용한다. 고급 수치 기능은 알고리즘만 작성하는 시간과 의미 검증 시간을 따로 추정한다.

| 단계 | 사용자에게 제공하는 결과 | 선행 조건 | 거친 기간 범위 |
| --- | --- | --- | --- |
| M0 | 사양, 데이터셋 대응, 수치·편집기 실험의 승인된 기준 | 없음 | 2~4주 |
| M1 | 설치·가입 없이 블럭으로 정적 계산하고 파일로 보관 | M0 | 6~10주 |
| M2 | 시간에 따라 변하는 이산 모델 실행과 TypeScript export | M1 | 6~10주 |
| M3 | 지원 범위 안에서 연속 동역학과 이벤트 실험 | M2 | 10~16주 |
| M4 | 데이터셋, 계층 모델, 실험 비교, 간단한 대시보드 | M2; 연속 모델은 M3 | 8~12주 |
| M5 | 고급 블럭의 의미 검증과 명확한 호환 경계 | 관련 M2~M4 기능 | 12~24주 이상, 기능 묶음별 재산정 |
| M6 | 지원 범위를 공개한 로컬 중심 공개 베타와 출시 검증 | M1~M4 통과, M5 지원 경계 확정 | 4~8주 |
| M7 | 검증된 추가 코드 타깃과 재사용 생태계 | M2 export 계약, M6 운영 경험 | 기능 묶음마다 8~16주 이상 |

M4의 데이터 관리·편집기 작업은 M3 엔진 작업과 일부 병행할 수 있다. M5 전체를 끝내야 M6를 시작하는 구조는 아니다. M6는 실제로 검증된 지원 범위로 출시하며, 미완성 고급 기능은 실험 표시 또는 비활성 상태로 남긴다. 선택 클라우드 기능도 로컬 제품의 출시 선행 조건이 아니다.

## 3. 공통 완료 기준

각 단계의 완료는 화면 구현이 끝난 시점이 아니라 아래 증거가 갖춰진 시점이다. 기능별 계약·검증은 [기술 백서](01-technical-whitepaper.md)에 상세화한다.

| 영역 | 모든 단계에 적용하는 완료 조건 |
| --- | --- |
| 실행 계약 | 입력 자료형·차원·단위·샘플시간, 초기값, 지원 파라미터와 미지원 조합을 문서화한다. |
| 수치 검증 | 블럭 단위 경계값과 대표 모델 fixture를 통과한다. 수치 허용오차를 모델별로 기록한다. |
| 진단 | 불완전 연결, 자료형·차원 불일치, 미지원 블럭과 실행 실패에 원인·위치·수정 방향을 제공한다. |
| 재현성 | 모델 버전, 실행 스냅샷, 엔진 버전, 설정, 난수 seed, 데이터 해시를 결과와 연결한다. |
| 자원 제한 | 파일 크기, 노드·연결 수, 배열 크기, 반복 횟수, 기록량과 실행 시간을 제한한다. 초과 시 복구 가능한 진단을 낸다. |
| 사용자 경험 | 키보드 주요 경로, undo/redo, 저장·재열기, 오류에서 복구하기를 대표 과제로 확인한다. |
| 대응표 | 새 기능·설정의 canonical ID, 원본 행, 단계, 상태, 검증 fixture를 [블럭 대응표](block-coverage.md)에 반영한다. |
| export | 해당 타깃에서 지원한 모델만 생성한다. 미지원 항목은 생성 전 실패시키고 원본 블럭 위치를 알려준다. |
| 안전성 | 사용자 문자열은 텍스트로 렌더링하고, 수식은 허용된 AST로 처리한다. `eval`, `new Function`, 임의 스크립트 실행을 실행 엔진의 전제로 삼지 않는다. |

블럭 상태는 `계획`, `실험`, `검증된 지원`, `부분 지원`, `외부 어댑터 연구`, `레거시 설명`, `미지원`으로 구분한다. 단순히 화면에 아이콘이 나타나거나 파일에 정의가 존재하는 상태를 `검증된 지원`으로 올리지 않는다. 상태 승격에는 계약, fixture, 사용자 진단과 export 지원 여부가 필요하다.

초기 자원 예산은 **노드 1,000개, 연결 5,000개, 모델 JSON 5 MiB, 데이터셋 20 MiB, 결과 기록 1,000,000개 scalar 값, 반복 상한 10,000회, 1회 실행 30초**를 제안한다. 기록량 1,000,000개의 float64 값은 원시 숫자 배열만 약 8 MB이며, 시간축·메타데이터·복사본·객체 비용은 추가된다. 예산은 데이터 총량과 전체 메모리 양쪽에서 검사한다. 시간 예산은 설정 가능하되 상한을 유지한다. 취소·watchdog 반응 1초 이내는 측정 목표로 두고 M0에서 기준 장비·브라우저·fixture와 함께 확정한다.

## 4. M0 — 사양 확정과 핵심 위험 실험

**목표:** 구현량을 세기 전에 실행 의미와 제품 중심 흐름을 결정하고, JS/TS로 가능한 범위를 작은 증거로 확인한다.

### 범위와 산출물

- 원본 385행의 대응표를 만들고 중복·별칭·구성·유틸리티·외부 의존·레거시를 분류한다. 원본 데이터셋은 수정하지 않는다.
- canonical 블럭 registry 형식을 정의한다. 포트·파라미터 schema, 자료형·차원, direct feedthrough, 상태, 샘플시간, 단위, 사전 설정과 표시 이름을 분리한다.
- 버전이 있는 모델 JSON, 연결 ID, 데이터 참조, 결과 manifest와 마이그레이션 원칙을 정한다.
- float64, boolean, 벡터·2D 행렬의 row-major 규약과 인덱스 기준을 고정한다. JavaScript 비트 연산의 의미를 일반 수학 정수형과 구분한다.
- `그래프 → 검증 → 실행 IR → Worker 실행`과 `동일 IR → TypeScript 생성`의 최소 프로토타입을 만든다.
- 지연을 포함한 피드백, direct feedthrough 순환 검출, 고정시간 tick, RK4 기초, 중단·자원 상한을 실험한다. Rate Transition의 period·offset·초기값·동시 hit는 기술 백서의 read-before-write 제안을 바탕으로 M0에서 필수 확정한다.
- 첫 사용자 과제를 위한 클릭 가능한 편집기 흐름을 만들고, 블럭 선택·연결·설정·실행·오류 수정의 이해도를 확인한다.
- 성능 기준 장비·브라우저 버전, 모델 fixture, 작업 시간 예산과 목표를 기록한다. 브랜드 이름과 CalcWeave.com 등록 가능성·상표 검토를 착수 전 체크리스트에 남긴다.

**선행 의존:** 없음. 사양 책임자, 수치 엔진 책임자, UI 책임자를 지정하되 소규모 팀에서는 한 사람이 여러 역할을 맡을 수 있다.

**비목표:** 전체 라이브러리 구현, 계정·협업·결제, Simulink 파일 import, 산업용 인증, 고급 solver, 자동 PID 튜닝, 임의 MATLAB/C 실행.

### 검증 fixture와 종료 게이트

| fixture | 기대 증거 |
| --- | --- |
| `F00-static-chain` | Constant → Gain → Sum → Display 계산값이 손계산과 일치하고 JSON 재열기 후 같음 |
| `F00-cycle` | 순수 산술 순환은 원인 경로로 거부하고, Unit Delay를 넣은 순환은 별도 상태 스케줄로 해석 가능 |
| `F00-state-order` | 같은 tick에서 이전 상태 읽기와 다음 상태 commit을 분리한 결과가 노드 배치 순서에 독립적 |
| `F00-ode-decay` | `dx/dt=-x`, `x(0)=1`의 RK4 결과가 해석해와 가까워지고 step을 줄일 때 오차가 감소 |
| `F00-budget` | 큰 모델·큰 배열·중단 요청이 탭 전체 정지와 무제한 할당으로 이어지지 않음 |

M0 종료 시 사양·registry·JSON/IR 계약, 약 20개를 목표로 한 M1 canonical 후보 목록, 지원 범위, 측정 결과, 수정된 추정이 승인되어야 한다. 후보 수는 이 단계에서 registry 기준으로 확정하며 분류 중복·별칭을 새 기능으로 세지 않는다.

**주요 위험과 축소:** 수치 의미가 불명확하면 UI를 확장하기 전에 해당 블럭을 보류한다. 편집기 라이브러리 도입이 지연되면 연결·드래그·키보드의 핵심 흐름만 평가한다. 성능이 예산에 못 미치면 UI 스레드에서 계산하는 방식으로 우회하지 않고 예산·버퍼 소유권·Worker 전달 방식을 재설계한다.

### 2026-10-02 착수 상태 — 부분 구현·검증 진행

이 절은 M0 착수 시점의 기록이다. 이후 타입·블럭 확장은 아래 M1 상태와 [M1 구현 계약](m1-contract.md)을 기준으로 한다.

[M0 구현 계약](m0-contract.md)에 JSON v1·registry·immutable IR·Worker·시간/상태/예산과 지원 경계를 기록했다. 현재 구현은 float64 scalar 8개 블럭이며, 정적 계산 6개에 Unit Delay와 고정 간격 RK4 Integrator 실험을 더한 범위다. 같은 IR의 TypeScript export는 정적·단일 step 이산 모델에 한정한다. M1 canonical 시작 후보는 22개로 정리했으며 boolean·vector·2D·단위 검사·수식 AST와 나머지 후보는 아직 구현하지 않았다. 대응표의 원본 385행을 보존하고 native 이름과 실제 registry ID가 일치하는 16행만 `M0 실험·스칼라 subset`으로 표시했다.

Rate Transition의 read-before-write 계약은 M2 구현 기준으로 채택했으나 다중 rate 실행과 executable fixture는 미구현이다. 수치 테스트·빌드·브라우저·성능 검증은 [M0 검증 기록](m0-validation.md)에 남겼다. 실제 초보 사용자 조사, CalcWeave.com 등록/소유권·상표 확인, 종료 승인은 수행하지 않았다. M1 기간 가정은 유지하고 첫 타입·shape 묶음의 실측 이후 다시 추정한다. **M0 종료 게이트는 부분 충족 상태이며 완료로 선언하지 않는다.**

## 6. M2 — 이산 시뮬레이션과 첫 실행 코드 export

**목표:** 사용자가 시간축과 상태를 가진 모델을 실행하고, 같은 의미를 가진 TypeScript 프로그램을 독립적으로 실행할 수 있게 한다.

### 범위와 산출물

- 정수 tick 기반 고정 샘플 실행과 명시적인 샘플시간을 도입한다. 멀티레이트는 base tick의 정수배만 지원하며, 그 밖의 조합은 거부한다.
- Unit Delay, 고정 Delay, 이산 적분기, 차분·간단한 필터, 이산 상태공간·전달함수의 승인된 부분집합을 우선 구현한다. `Memory`는 major-step 의미를 다루는 M3로 분리한다.
- Step·Ramp·Sine·Pulse, Clock·Digital Clock, seed가 있는 난수, 승인한 repeating sequence를 추가한다.
- 이전 committed 상태 고정 → source·현재 입력에 의존하지 않는 상태 출력 준비 → direct-feedthrough 출력과 조합 노드의 의존 DAG 평가 → next-state 계산 → 일괄 commit 순서를 고정한다. 필터·PID는 상류 입력 평가 뒤 실행하고, 모든 next-state 계산은 이전 committed 상태를 사용한다. 초기값·reset 우선순위·동일 tick 순서와 배열 갱신도 이 계약을 따른다.
- 논리 에지 검출, 32비트 이하 정수·비트의 승인된 폭·부호·오버플로 정책, Rate Transition의 명시적 전달 규약, 기초 1-D Lookup과 이산 범위 검사를 검증한다. 동시 hit에서 이전 발행값을 읽는 경계 버퍼와 첫 발행 전 초기값을 검증하며 전달 지연을 드러낸다.
- 시계열 결과, Scope·Display, 일시정지·재개·reset, 기록 상한과 샘플 단위 진단을 제공한다. 전체 원시 기록과 화면용 downsampling을 구분한다.
- `model.ts`, 최소 런타임, 예제 실행 fixture, manifest를 export한다. 모델 hash·엔진/타깃 버전·데이터 참조·seed·설정을 포함하고 숨은 클라우드 런타임 없이 오프라인 실행 가능하게 한다.
- export 생성 전에 전체 모델의 타깃 지원 여부를 검사한다. 안전한 AST/템플릿으로 식별자·문자열을 생성하고, 오류 위치를 원본 블럭 ID에 대응시킨다.

**선행 의존:** M1의 실행 IR·검증·프로젝트 저장·자원 제한. export는 UI 정의를 별도로 번역하지 않고 실행 IR과 같은 계약을 사용한다.

**비목표:** 임의 가변 샘플시간, 연속 solver, 샘플시간 의미를 무시한 순환 처리, 모든 PID 옵션, 비트 수준 고정소수점, Python/C/HDL export, 사용자 코드의 무제한 실행.

## 7. M3 — 연속·혼합 시뮬레이션

**목표:** 실제 수치 오차와 지원 한계를 설명하면서 연속 동역학을 다룬다. 고정 step 실행부터 검증한 뒤 적응 step과 이벤트로 확장한다.

### 범위와 산출물

- **M3a:** 고정 step RK4, Integrator·Second-Order Integrator, 일반 ODE 형태의 State-Space·Transfer Fcn·Zero-Pole, 직접 계수 입력 PID의 제한된 지원을 구현한다.
- **M3b:** 적응 step RK45, 절대·상대 오차, 최소·최대 step, 거부 step·평가 횟수 상한, solver 통계를 도입한다. 초기 지원은 비강성 ODE로 제한한다.
- 연속 상태·이산 tick·출력 샘플 시점을 분리한다. 연속 source는 각 RK stage 시각에서 재평가하고, hold는 이산·외부 sampled 입력에 적용한다. RK 내부 stage·거부 step에서 이산 상태를 commit하거나 부작용을 실행하지 않는다.
- Hit Crossing·Relay·Saturation 등 혼합 동작의 zero crossing, 이벤트 시간 허용오차, 동일 시각 우선순위, reset·재시작, chattering 상한을 정의한다. event 위치 확정 전 trial history·로그를 commit하지 않고, 가장 이른 event까지 유효 구간을 확정한 뒤 reset·동시 tick·재시작을 처리한다.
- `Memory`의 major-step 의미, First Order Hold·Zero-Order Hold, 승인된 고정 Transport Delay의 이력·보간 정책을 구현한다. 가변 지연은 별도 검증 전 `계획`으로 둔다.
- Derivative는 잡음·불연속 신호에서의 제한을 표시한다. 미분 블럭을 넣었다는 이유만으로 모든 입력에서 안정적인 수치 미분을 보장하지 않는다.
- run manifest에 solver·step·허용오차·event 정책을 기록한다. 수렴 실패·최소 step·시간 예산 초과 시 마지막 유효 상태와 이유를 제공한다.
- 연속 모델의 TypeScript export를 지원하려면 동일 solver·이벤트 계약과 해당 fixture parity를 먼저 통과시킨다.

**선행 의존:** M2의 tick·상태·결과 계약. M3a의 정확도 게이트를 통과한 후 M3b를 승격한다.

**비목표:** 강성 ODE solver, 임의 DAE·Algebraic Constraint, 모든 Descriptor State-Space, 엔터티 시뮬레이션, 산업용 실시간 보장, PID 자동 튜닝, 물리 도메인 툴박스 완전 호환.

### 검증 fixture와 종료 게이트

| fixture | 기대 증거 |
| --- | --- |
| `F03-decay` | 지수 감쇠의 해석해와 비교하고 step halving에서 수렴을 확인함 |
| `F03-oscillator` | 조화 진동의 위상·진폭 오차를 범위로 기록하고 독립 solver와 교차 비교함 |
| `F03-step-response` | 1차 시스템의 step 응답·초기값·정상값이 해석 결과와 일치함 |
| `F03-crossing-reset` | threshold crossing, 적분기 reset과 이산 tick이 같은 시간일 때 규정된 결과를 냄 |
| `F03-delay-memory` | 고정 지연의 이력 보간과 Memory의 major-step 동작을 Unit Delay와 구분해 검증함 |
| `F03-failure` | 어려운 모델에서 정확도·수렴 조건을 못 맞추면 무의미한 성공값 대신 종료 사유를 냄 |

수치 fixture는 `|actual-reference| ≤ atol + rtol × |reference|` 형태의 허용오차를 모델별로 명시한다. event 시간 오차와 불연속 지점 전후 출력은 별도로 판정한다. 해석해가 있는 모델, 독립 solver, step halving을 함께 사용한다. MATLAB 설치와 Simulink golden 결과를 이 게이트의 필수 조건으로 삼지 않으며, 향후 비교 데이터를 얻으면 지원 조건을 맞춘 별도 호환 근거로 기록한다.

종료 게이트는 M3a/M3b 각각의 수치 기준, 이벤트 순서, 내부 stage의 상태 불변성, 실패 진단, 자원 상한 통과다. 어려운 모델 모두를 자동 감지할 수 있다고 주장하지 않고, 테스트한 비강성 범위와 실패 조건을 공개한다.

**주요 위험과 축소:** 가장 큰 위험은 기능이 작동해 보이지만 오차·이벤트가 잘못된 상태다. M3b가 지연되면 고정 step RK4와 지원된 사건 없는 모델만 `검증된 지원`으로 제공한다. 가변 지연·복잡 PID·다중 불연속 모델을 보류한다. 시뮬레이션 의미를 검증하지 못하면 넓은 지원 목록으로 보완하지 않는다.

### 2026-10-02 구현 기록

현재 M3a·M3b의 승인 subset을 구현했다. registry는 57종이며 M2의 정적 26종·순수 이산 44종을 보존하고 12종을 추가했다. 신규는 Second Order Integrator, scalar SISO State Space·Transfer Fcn·실수 Zero Pole, parallel filtered PID·Derivative, Memory·Zero Order Hold·causal First Order Hold·고정 Transport Delay, Hit Crossing·Relay다. Integrator는 초기값과 rising reset만 제공하고 limited Integrator·anti-windup·MIMO·복소수·강성 solver·DAE는 지원하지 않는다.

출력 격자는 `execution.step`, 내부 적분은 normalized `execution.solver`, 이산 base grid는 `solver.discreteStep`으로 분리한다. RK4 고정 간격과 RK45 오차 제어는 원시 출력·사건·이산 경계에서 구간을 끝내며 각 stage의 연속 source를 실제 시각에 평가한다. 승인 전 trial·거절 단계의 이산 상태·난수·Memory·지연 이력은 commit하지 않는다. 동시 시각에는 사건·reset → 이산 tick → 관측을 적용하고 tick 내부 RT의 read-before-write를 유지한다.

연속 scalar ODE 영역에 M2 boolean·벡터·2D 이산 영역을 섞을 수 있다. 연속→이산 입력은 scalar Zero Order Hold로 명시하고 이산→ODE는 causal held 입력을 사용한다. 다른 이산 rate는 RT를 요구한다. 등록하지 않은 연속 불연속 연산이 미분 경로에 들어가면 사전에 거절한다. Hit Crossing 직접 출력 또는 이산 held boolean만 Integrator reset 제어로 허용하며 일반 Compare를 정확한 사건 검출로 오인하지 않는다.

솔버 설정·횟수 상한, 사건 시각과 solverStatistics를 결과·manifest에 기록한다. 한도·수치 실패는 `failed`와 마지막 승인 상태·유효 원시 샘플의 partialResult를 제공한다. pause/resume/cancel/reset은 기존 snapshot 의미를 유지하며 제어된 실패 예제도 제공한다. 현재 M3 타깃은 import 없는 TypeScript와 SHA-256 manifest ZIP으로 연속·혼합 모델을 내보내며 원시 시간축·상태·메모리·사건·실패 결과의 독립 실행 parity를 확인한다.

정확한 옵션과 수치는 [M3 구현 계약](m3-contract.md), 분석해·수렴·혼합 순서·자원/실패·브라우저·export 검증의 실제 결과는 [M3 검증 기록](m3-validation.md)을 따른다. 원자료 385행과 M0~M2의 당시 기록은 보존한다. 외부 엔진 비교, CalcWeave.com 소유권·상표 확인과 실제 초보 사용자 조사 게이트는 소급 완료하지 않는다.

## 8. M4 — 데이터 관리, 모델 계층, 실험 비교

**목표:** 한 번 실행한 도식을 재사용 가능한 실험으로 만들고, 데이터 입력과 결과 비교를 한 작업 공간 안에서 이어 간다.

### 범위와 산출물

- CSV·JSON 데이터 import, schema·열 유형·단위·시간축 미리보기, 결측·비정상값 정책, 정렬·중복 시간 진단, 데이터 hash와 프로젝트 참조를 구현한다.
- From File/From Workspace/Playback 등의 목적을 로컬 데이터셋·시계열 블럭으로 제공한다. MATLAB workspace나 임의 로컬 경로 접근으로 해석하지 않는다.
- Source 편집과 승인된 보간·구간 밖 동작을 제공한다. spreadsheet는 필요 시 검증한 형식·subset을 추가하며 CSV를 첫 교환 형식으로 사용한다.
- 결과 CSV·JSON export, 실행 이력, parameter sweep과 run 비교를 구현한다. sweep도 전체 실행 횟수·기록량·시간 예산을 공유한다.
- Subsystem·입출력 포트·Bus의 승인된 의미, 계층 이동·이름공간·재사용 참조와 버전 변경 진단을 도입한다. 실행 IR에서 flatten하거나 호출할 때 상태·실행 순서를 보존한다.
- 기본 Dashboard의 Slider·Toggle·Display·Gauge·Scope 등 검증한 위젯을 제공한다. M4 기본 변경은 다음 run에 적용한다. live tuning을 추가하려면 별도 capability로 검증하고 적용 tick·값·순서의 입력 이벤트 로그를 manifest에 보존한다.
- DocBlock·Model Info·지원표, 타입·shape·단위의 차원 대수, 단위 변환을 확장한다. Goto/From·Data Store를 도입할 경우 이름공간·writer 순서를 먼저 정의한다.
- 문자열은 데이터 정리의 승인된 함수부터 추가한다. CSV 내보내기 시 수식으로 해석될 수 있는 셀의 보호 정책을 별도로 제공한다.

**선행 의존:** M2의 기록·run manifest·tick 의미. 연속 데이터·계층 모델은 M3의 해당 solver 지원을 따른다.

**비목표:** 실시간 공동 편집, 무제한 데이터 처리, 전체 Excel 기능, 외부 DB 자동 연결, 임의 Dashboard callback 코드, 인터넷 데이터 자동 수집, 서버 저장의 기본 강제.

### 2026-10-02 M4 구현 기록

registry 64종과 CSV·JSON 데이터 가져오기/정리/미리보기/버전/hash/재생, 결과 CSV·JSON, 로컬 실행 이력, 최대 16회 파라미터 반복과 3개 실행 비교를 구현했다. sweep은 전체 시간·기록·가중 연산 예산을 공유하고 실패·취소 시 완료 결과를 보존한다. 서브시스템은 프로젝트 내장 정의·입출력·독립 상태·계층 이동·편집·명시적 인스턴스 갱신을 제공한다. Bus는 같은 타입·단위의 scalar 두 필드로 제한한다. 명시적 affine 단위 변환과 승인 목록 안의 곱·나눗셈·제곱·역수·제곱근 차원 대수를 추가했다.

Slider·Toggle·Display·Gauge·Scope는 다음 실행 snapshot 또는 완료 결과를 사용한다. DocBlock·Model Info와 노트는 계산과 분리한 일반 텍스트다. 데이터·계층 모델의 독립 TypeScript/manifest ZIP 재현을 검증하고 예제 3개를 추가했다. 실제 종료 판단은 [M4 구현 계약](m4-contract.md)·[M4 검증 기록](m4-validation.md)에 기록한다. 기존 M1~M3 수치 증거는 보존하고 현 엔진의 회귀 결과는 별도 파일에 둔다.

XLSX·MAT, 일반 문자열 계산, 이질·중첩 Bus, 외부 모델 파일 참조, live tuning과 임의 callback, 모든 과거 원본 파일을 보관하는 데이터 저장소는 승인 범위에 포함하지 않는다. 사용자 조사·외부 엔진 비교·공개 배포를 소급 완료하지 않는다. M5는 다음 요청에서 해당 기능 묶음의 실행 계약과 fixture부터 확정한다.

| 수명주기·사용자 함수 | Initialize/Reset/Reinitialize/Terminate, 제한 수식과 승인 plugin 계약 | MATLAB/System/S-function/C Caller 의미의 동일 재현은 별도 외부 어댑터 연구 |

각 묶음을 하나의 mini-release로 처리하고, `계약 → fixture → prototype → 타깃/진단 검사 → 검증된 지원` 순으로 승격한다. 모든 원본 행은 canonical 기능·사전 설정·독립 대체·유틸리티·레거시 설명·외부 어댑터 연구·미지원 중 하나에 연결한다. 대응이 완성되었다는 사실과 실행 지원이 완성되었다는 사실을 별도 지표로 보고한다.

**선행 의존:** 기능 묶음별 M2 tick/M3 solver/M4 타입·계층·데이터 계약. 예를 들어 메시지는 이벤트 스케줄이, 고정소수점은 자료형·export 타깃 지원이 선행한다.

**비목표:** 하나의 출시에서 385행 전부의 실행·파라미터·코드 생성 100% 동등성, 모든 Simulink 모델 import, 강성·고차 DAE 일반 solver, SimEvents 네트워크 전체, 외부 MATLAB 및 native C 코드의 브라우저 직접 실행.

### 검증 fixture와 종료 게이트

| fixture | 기대 증거 |
| --- | --- |
| `F05-complex` | magnitude/phase·실/허수·켤레 전치의 기준값과 배열 shape가 일치함 |
| `F05-fixedpoint` | 승인 폭·부호·스케일 조합의 경계값·포화·wrap·rounding을 정수 기준값과 비교함 |

M5의 단계 종료는 모든 고급 블럭 구현 완료 선언이 아니다. 선택한 기능 묶음은 검증된 지원으로 승격하고, 미선택 묶음과 외부 의존의 경계를 공개하는 게이트다. 지원 범위를 확대할 때마다 해당 fixture와 export parity를 다시 통과시킨다.

**주요 위험과 축소:** 고정소수점·메시지·DAE를 동시에 개발하면 검증 비용이 급증한다. 실제 사용자 요구·공통 의존·기준 데이터 확보를 바탕으로 하나씩 선택한다. 복소수·n-D Lookup·제한 메시지는 독립 묶음으로 출시할 수 있다. 수치 선형화·DAE·외부 runtime 어댑터는 근거가 없으면 연구 상태로 남긴다.

### 2026-10-02~03 M5 선택 기능 구현 기록

계약·독립 fixture·진단·export 검증 대상으로 실수 행렬, 2D Lookup/Prelookup, 1~32bit 고정소수점 양자화 경계의 세 묶음을 선택했다. registry 10종을 추가해 총 74종(정적 43종)이며 선형 방정식·LU, 비균일 보간표, 반올림·overflow 예제 3개를 추가해 총 27개다. 기존 M1~M4 증거를 보존하고 현 엔진의 회귀 결과는 별도 기록한다. 실제 수치·입출력·단위·정밀도·예산은 [M5 계약](m5-contract.md), 확인 결과는 [M5 검증 기록](m5-validation.md)에 남긴다.

실수 곱/전치·2D 표·Prelookup만 원자료의 해당 subset으로 연결한다. 고정소수점 quantizer는 Data Type Conversion 목적의 독립 대체이며 일반 타입 전파가 아니다. determinant/inverse/solve/Cholesky/LU는 원자료에 없는 CalcWeave 추가 기능으로 따로 표시한다. Hermitian Transpose·복소수, n-D·동적 표·Interpolation Using Prelookup, 64bit·일반 fixed-point 산술, 메시지·조건/반복·함수 호출·가변 지연·DAE·선형화와 외부 runtime은 이번 승인에 포함하지 않는다. 미선택 기능의 실행을 성공했다고 표시하지 않으며 사용자 조사·외부 엔진 검증·M6 공개 배포를 소급 완료하지 않는다.

## 11. M7 — 코드 타깃과 생태계 확장

### 2026-10-03 첫 추가 타깃·재사용 모델 구현 기록

Python `python-m7-v1`을 첫 추가 타깃으로 선정했다. 승인된 정적·이산 typed 모델을 표준 라이브러리 독립 코드와 실행 묶음으로 생성하며 연속·M5 고급 기능은 생성 전에 위치·이유를 진단한다. registry의 타깃 표시는 생성기와 같은 승인 상수를 사용한다. TypeScript export와 기존 수학/저장/오프라인 계약은 유지한다.

임의 커널을 설치하는 대신 승인된 기존 registry로 만든 선언형 모델 패키지를 먼저 제공한다. P-256 서명·hash·엔진/schema/registry·권한 검증과 출처에서 별도로 받은 공개키 fingerprint 수락을 적용한다. native 모델은 구문·편집 가능 모델·실행 가능성과 외부 변환 여부를 분리한다. 정확한 실행·권한·입력 상한과 실제 검증은 [M7 계약](m7-contract.md)·[검증](m7-validation.md)에 기록한다. C/C++·MATLAB/S-function·WASM·외부 형식 adapter·지속적인 signer identity/폐기 목록은 이번 승인 밖이며 M6 공개 배포/사용자 관찰을 소급 완료하지 않는다.

**목표:** 검증한 모델을 여러 실행 환경에 가져가고, 재사용 가능한 블럭·모델을 확장한다. 실제 요구가 있는 타깃부터 하나씩 추가한다.

### 범위와 산출물

- Python 등 첫 추가 타깃을 선정해 지원 자료형·연산·solver·라이브러리 의존·파일 구성을 정의한다. C 계열은 메모리·오버플로·런타임·컴파일러 조건까지 별도 계약한다.
- 타깃별 생성 전 검사, manifest, 런타임·예제·fixture, 원본 블럭 대응, 수치 허용오차와 parity를 제공한다.
- 서명·버전·지원 계약·권한이 있는 블럭 package, registry schema 검증, 예제 모델 공유와 호환 migration을 단계적으로 도입한다.
- 외부 MATLAB/System/S-function/C 사용자 코드와 Entity Transport Delay 같은 엔터티 기능은 별도 어댑터 연구로 처리한다. 결과 교환, 외부 실행기 연결, 제한된 WASM 배포 등 후보는 실행 위치·권한·의존성·검증이 확보된 뒤 선택한다.
- 모델 import는 파일 파싱 성공과 실행 의미 일치를 구분한다. 지원하지 않는 블럭·파라미터·자료형·sample/event 의미를 명시적으로 보고한다.

**선행 의존:** M2의 IR/export 계약, 확장 타깃이 사용하는 M3~M5 기능, M6의 실제 사용·회귀 검증 체계.

**비목표:** native C/C++ 코드의 무조건적인 브라우저 직접 실행, MATLAB runtime 자동 제공, arbitrary plugin의 Worker만으로 완전한 보안 격리, HDL/임베디드 실시간·안전 인증, 모든 Simulink 모델 round-trip.

### 검증 fixture와 종료 게이트

| fixture | 기대 증거 |
| --- | --- |
| `F07-target-parity` | 승인된 대표 모델에서 브라우저·TypeScript·새 타깃의 시간축·출력·상태·실패 규칙이 일치함 |
| `F07-target-reject` | 타깃 미지원 기능은 생성 전에 원본 블럭 위치와 이유로 거부함 |
| `F07-package-contract` | 손상·미승인·버전 불일치 package가 모델 상태를 훼손하거나 임의 권한을 얻지 못함 |
| `F07-import-boundary` | 파싱·변환·실행 가능의 상태가 구분되고 손실된 의미를 성공 import로 숨기지 않음 |

새 타깃·어댑터·package 각각에 별도 종료 게이트를 둔다. 파일이 생성된 것만으로 실행 코드 지원을 선언하지 않는다. 컴파일·실행 환경을 요구하는 타깃은 그 조건과 실제 검증 환경을 export 문서에 포함한다.

**주요 위험과 축소:** 타깃 수가 늘면 타입·solver·라이브러리 차이로 유지 비용이 커진다. 사용 빈도가 높은 제한 모델 subset부터 지원한다. adapter 연구가 성공하지 않으면 독립 TS Expression/승인 package 대체와 데이터 교환만 제공하고 원래 runtime 동등성을 주장하지 않는다.

## 13. 우선순위 변경 규칙과 첫 착수 순서

사용자 요청은 **필요한 사용자 과제, 선행 실행 의미, 기준 데이터·fixture 확보, 재사용되는 기능 수, 유지 비용**으로 평가한다. 디자인·수치·보안의 종료 게이트를 충족하지 못하는 기능은 요청 빈도가 높아도 `실험`에서 승격하지 않는다. 우선순위 변경은 원본 대응표의 단계·상태, 기술 지원표와 release 예제를 함께 수정한다.

1. M0에서 385행 대응표와 약 20개 canonical M1 후보를 확정한다.
2. 정적 실행 IR·저장 형식을 만들고, 산술 체인·자료형 오류·순환·예산 fixture를 먼저 통과시킨다.
3. 같은 fixture를 사용하는 최소 편집기와 로컬 저장·복구 흐름을 붙인다.
4. 실제 처음 쓰는 사람의 과제를 확인하고 M1 후보·화면을 조정한다.
5. 이산 상태·tick 계약을 확정한 뒤 M2 블럭과 TypeScript export를 함께 늘린다.
6. 해석해·독립 solver 검증을 바탕으로 M3를 고정 step, 적응 step·event 순서로 진행한다.
7. 데이터·계층·실험 흐름을 확장하고, 실제 요청으로 M5 고급 묶음을 선택한다.
8. 검증된 범위와 운영·보안 증거로 M6를 판단한 뒤 추가 언어·어댑터·생태계로 확장한다.

단계별 보고는 기능 개수만 나열하지 않고 **완료한 사용자 과제, 검증된 실행 범위, 통과한 fixture, 남은 위험·지원 제한, 변경한 범위와 다음 게이트**를 포함한다. 일정이 늘어날 때는 정확도·데이터 보존·권한 검증을 빼기보다 지원 기능의 수와 복잡도를 줄인다.
