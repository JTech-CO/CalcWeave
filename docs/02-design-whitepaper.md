앱0.8.1의 [GitHub Pages 웹 베타](https://jtech-co.github.io/CalcWeave/)와 M9 앱0.10.1의211종·지원표·Worker·오프라인9검사는 이전 배포 기록이다. 현재 검증된 공개 버전은 M13·M14·M15 통합 앱0.16.0/337종이다. [배포 검증](pages-validation.md)과 [M8~M16 전체 대응 후속 로드맵](05-simulink-coverage-roadmap.md)을 따르며 목표 도메인·실제 초보자 조사·전체 옵션 동등성은 별도다.

M9 시점의 로컬·공개 버전은211종 블럭과39예제를 제공했다. 당시 예제는 기초·신호 입력·이산 상태·연속/혼합·데이터/도식·행렬/표/양자화의6범주였으며 M13은69예제/11범주,M14와 현재 M15는75예제/12범주다. 제목·설명·블럭 ID 검색,Enter/방향키/Escape와 IME 구분, 작은 화면의 메뉴 배치를 유지한다. 빠른 추가 버튼의 K와 예제 버튼의 문자 v는 제거하고 dropdown은 SVG 아이콘을 쓴다. 단축키와 접근성 설명은 유지한다. 라이브러리는 신규 블럭의 식별 기호를 제공하며 캔버스는 종류 이름·핵심 값만 표시하는 간결한 계약을 유지한다. 검정/밝은 회색 테마, 본문16px/보조14px, 도식과 결과의 좌우 배치를 유지한다. 이전 [확장 계약](catalog-contract.md)·[검증](catalog-validation.md)도 단계 기록으로 보존한다.

M9의4개 학습 예제는 이산 필터 응답·이전 세 샘플·샘플주기와 순환 카운터·2DOF PI 목표 가중치다. 속성에서는 z⁻¹/descending-z·실현 구조·IC 좌표·reset/enable, 초 단위Ts와 period/offset, 지연의 zero-lag와 floor 발행 경계를 설명한다. 공유 preset이나 독립 설정 대체를 원본 전체 옵션 지원으로 표시하지 않는다. M9 당시 Python은 승인51개만 안내했고 M9 블럭은 TypeScript 타깃의 이유와 원본 노드 위치를 보여 준다.

M7에서 코드 타깃 선택·모델 패키지·가져오기 보고 창을 추가했다. Python 타깃은 현재 도식의 지원 여부와 원본 위치별 이유를 먼저 보여주며, 파일로 받은 서명만으로 출처를 신뢰하지 않고 별도로 확인한 fingerprint 입력을 요구한다. native 모델의 계산 오류는 편집할 수 있고 외부 형식 변환은 수행하지 않았음을 표시한다. [M7 계약](m7-contract.md)·[검증](m7-validation.md)은 단계 기록으로 보존한다.

CalcWeave의 첫 경험은 “블록 세 개를 연결해 내가 예상한 값을 확인한다”가 되어야 한다. 이후 같은 도식에서 시간에 따른 변화, 외부 데이터, 재사용 가능한 모델, 프로그램 코드까지 확장한다. 사용자는 설치나 코드 문법 학습을 시작 조건으로 요구받지 않는다.

이 문서는 CalcWeave를 위한 독립적인 화면·상호작용·문구 설계안이다. Simulink의 라이브러리 분류를 탐색 기준 자료로 활용하되, 그 화면 배치나 모든 동작을 그대로 재현하는 것을 목표로 삼지 않는다. 수치 계산의 의미, 지원 자료형, 솔버, 보안 경계는 [기술 백서](01-technical-whitepaper.md), 구현 순서와 완료 조건은 [마일스톤 로드맵](03-milestone-roadmap.md), 블록별 지원 범위는 [블록 커버리지](block-coverage.md)를 따른다.

M5 시점에는 라이브러리74종·학습 예제27개를 제공했다. 행렬의 행·열·단위, P·A=L·U의 다중 출력, 2D 표의 축 대응, 양자화된 실수와 stored integer의 차이를 속성 패널과 실제 예제로 설명한다. 캔버스에는 영어 블럭명·핵심 값만 표시하고 상세 계약은 선택한 블럭의 속성에 둔다. 도식·데이터·실험·대시보드·노트, 다음 실행 snapshot·시간 범위·이력 비교 흐름을 유지한다. 신규 실제 범위와 증거는 [M5 구현 계약](m5-contract.md)·[검증 기록](m5-validation.md)을 따른다.

M2 시점에는 라이브러리 45종에서 시간 입력·typed 상태·정수 rate를 추가했다. inspector의 period/offset, Rate Transition 안내, 실제 Worker ack 뒤 일시정지·재개, 모델을 보존하는 초기화와 전체 배열 sample 조회는 M3에서도 유지한다. 정지 중 편집은 다음 run에 적용한다. 중성 다크·라이트, 읽기 크기, 간결한 블럭, 좌우배치, 빠른 추가·복사·복구·최초 도식 맞춤과 사용자 지정 캔버스 조작은 [SANE 화면 수정 기록](04-sane-design-revision.md)을 따른다. 이전 단계의 증거는 [M2 검증 기록](m2-validation.md)에 보존한다. 아래 설계 전체와 초보 사용성 목표가 완료·입증되었다는 뜻은 아니다.

## 1. 이 문서의 전제와 확신 수준

## 2. 브랜드와 경험 원칙

### 2.1 브랜드 표현

- 이름은 `CalcWeave`로 고정한다. 로고·문서·프로젝트 파일의 표시 이름에 같은 대소문자를 쓴다.
- 제품 설명은 “블록으로 연결하는 수학 계산과 시뮬레이션”을 우선 사용한다. 사용자가 알고 있는 용어로 설명하고 블록 기반 모델링의 전문 용어는 필요할 때 덧붙인다.
- 주된 브랜드 이미지는 **값과 관계를 엮어 이해 가능한 모델을 만드는 작업**이다. 블록의 연결선과 명확한 입출력 구조를 시각적 중심으로 삼는다.
- 로고·아이콘·예제 도식은 독립적으로 제작한다. MathWorks의 로고·아이콘·스크린샷을 CalcWeave 자산으로 사용하지 않는다.
- “Simulink 호환”, “MATLAB 없이 MATLAB 실행” 같은 문구는 별도 검증 없이 사용하지 않는다. 참조 문서에 대응 블록 이름을 보여 주는 것과 모델·결과·코드의 호환성은 다른 약속이다.
- 목표 도메인은 기획 문서와 브랜드 메모에 기록하되, 초기 화면의 파일 공유·도움말 링크에 확보되지 않은 주소를 작동하는 링크처럼 넣지 않는다.

### 2.2 여섯 가지 경험 원칙

| 작은 성공에서 시작 | 빈 캔버스에 바로 “첫 계산 만들기”와 작은 예제를 제공한다. 전체 분류 목록을 첫 화면에 펼치지 않는다. |
| 도식이 계산을 설명 | 블록의 주요 매개변수와 연결 방향을 캔버스에서 읽을 수 있다. 결과에서 문제의 입력·블록으로 돌아갈 수 있다. |
| 쉬운 말과 정확한 의미를 함께 사용 | `1단계 지연 · Unit Delay`처럼 설명과 정식 이름을 같이 제공한다. 비슷한 이름의 다른 동작을 한 가지 기능으로 합치지 않는다. |
| 복잡성은 필요할 때 드러냄 | 솔버 허용오차·자료형·샘플시간 등은 접을 수 있어도 현재 적용값과 영향을 숨기지 않는다. |
| 오류는 고칠 위치를 안내 | “실행 실패”만 알리지 않고 블록·포트·문제 값·수정 방법을 제공한다. 자동 수정은 명시적인 선택으로 수행한다. |
| 결과의 출처를 신뢰 가능하게 표시 | 실행한 모델 버전·입력 데이터·설정과 현재 모델의 차이를 표시한다. 이전 결과를 새 계산 결과처럼 보이게 하지 않는다. |

## 3. 사용자와 핵심 작업

사용자 조사는 아직 수행하지 않았다. 아래 구분은 초기 모집과 작업 설계에 사용할 가설이며, 사용자를 고정된 등급으로 분류하는 권한 체계가 아니다.

### 4.2 첫 화면의 라이브러리

기본 탐색은 사용자 작업을 기준으로 한다. 내부 라이브러리 ID와 원본 자료의 분류는 별도로 유지한다.

| 기본 그룹 | 사용자의 질문 | 예시 |
| --- | --- | --- |
| 입력 | 무엇을 계산할까? | 값 · Constant, 시간 신호 · Step/Sine Wave, 입력 포트 |
| 계산 | 어떤 관계를 만들까? | 더하기 · Sum, 곱하기 · Product, 배율 · Gain, 비교 |
| 시간·상태 | 이전 값이나 시간 변화가 필요한가? | Unit Delay, 이산 적분, 연속 적분, 필터 |
| 배열·연결 | 여러 값을 어떻게 묶거나 선택할까? | 벡터 결합, 선택, 행렬 연산, 버스 |
| 결과 | 무엇을 확인하고 기록할까? | 값 표시, 시간 그래프, XY 그래프, 검증 |
| 모델 구성 | 큰 도식을 어떻게 관리할까? | 입출력, 서브모델, 주석, 조건부 실행 |

처음에는 M1에서 실행 가능한 그룹과 블록만 기본으로 보여 준다. `전체 목록 / 지원 예정 보기`는 별도로 제공한다. 미지원 블록을 클릭하면 지원 단계와 대안을 설명하며 캔버스에는 실행 가능한 블록처럼 삽입하지 않는다.

전문 사용자를 위한 `참조 분류 보기`에서는 dataset의 21개 분류를 확인할 수 있게 한다. 참조 분류는 독립 제품의 기본 탐색보다 앞에 두지 않는다. 분류 간 중복 항목은 같은 CalcWeave 블록 정의의 여러 탐색 경로로 처리한다.

### 4.3 검색과 별칭

- 검색 대상: 한국어 표시명, 영문 정식명, 기능 동사, 기호, 의미가 동일한 사전 구성 별칭. 정규 블록 ID는 UI 언어와 무관하게 유지한다.
- 검색 결과 한 행: `한국어 설명 · English Name`, 짧은 기능 설명, 그룹, 현재 실행 방식의 지원 상태.
- 빈 검색 결과: 철자 수정 제안, 더 넓은 기능 검색, 미지원 목록 확인을 제공한다. 지원하지 않는 기능을 임의로 가장 비슷한 블록에 연결하지 않는다.
- Quick Insert 대응 항목은 별도 엔진 기능으로 부풀리지 않는다. 예를 들어 더하기와 빼기는 동일 계열의 명시적인 사전 구성으로 탐색할 수 있다.
- 사용자는 `+`, `더하기`, `덧셈`, `sum`, `add`로 관련 기능을 찾을 수 있어야 한다. 영문 exact match가 있는 결과에는 그 사실을 표시한다.
- `적분`, `integrator`, `누적` 검색 결과는 연속 적분과 이산 누적을 각각 설명한다. `미분`, `차분`도 같은 원칙을 적용한다.
- `사인`, `sin`, `sine` 검색은 수학 함수, 시간 파형, 조회표 계열을 역할별로 나눈다. 같은 이름의 결과를 하나로 합치지 않는다.
- `Display`는 값 표시와 Dashboard 표시의 역할을 구분한다. `Delay`, `Unit Delay`, `Memory`도 원본 자료에 명시된 의미 차이를 유지한다.

| 검색어 예시 | 제안 결과 | 확인 문구 예시 |
| --- | --- | --- |
| `곱`, `multiply`, `*` | 요소별 곱, 행렬 곱 | `행렬 곱: 왼쪽 열 수와 오른쪽 행 수가 같아야 합니다.` |
| `평균` | 지원되는 요소 집계 또는 명시적인 예제 구성 | 독립 평균 블록이 아직 없으면 `합계 ÷ 개수 예제`로 표시 |
| `지연` | 1단계 지연, 여러 단계 지연, 시간 지연 | `이 블록은 이산 실행에서만 사용할 수 있습니다.` |
| `그래프`, `scope` | 시간 그래프, XY 그래프 | 시간 축과 두 입력값 축을 구분 |

별칭 목록은 버전 관리하는 블록 카탈로그에 둔다. UI 번역 문자열에 숨겨서 유지하지 않는다. 검색 회수·실패 사례는 개인정보를 수집하지 않는 로컬 사용성 시험으로도 검증할 수 있다.

## 5. 작업 공간과 반응형 레이아웃

### 5.1 데스크톱 기준 배치

기준 화면은 **1440 × 900 CSS px**이다. 사용자 피드백을 반영해 중앙 작업 공간을 캔버스 왼쪽·계산 결과 오른쪽으로 배치한다. 아래는 현재 M1의 기본 치수이며 글자 확대·가용 공간에 따라 재배치한다.

| 영역 | 기본 치수 | 역할 |
| --- | ---: | --- |
| 앱 헤더 | 최소 높이 72 px, 내용에 따라 줄바꿈 | 모델 이름·저장 상태·파일·도움말 |
| 작업 도구줄 | 최소 높이 65 px, 내용에 따라 줄바꿈 | 새 모델·빠른 추가·선택·실행 방식·실행·정지 |
| 왼쪽 라이브러리 | 기본 너비 250 px | 검색·그룹·블록 설명 |
| 오른쪽 속성 패널 | 기본 너비 312 px | 선택 대상·매개변수·포트·지원 |
| 중앙 왼쪽 캔버스 | 기본 약 558 px, 작업 공간의 전체 높이 | 모델 도식과 경로 |
| 중앙 오른쪽 결과 패널 | 기본 너비 320 px, 넓은 화면에서 최대 420 px, 캔버스와 같은 높이 | 결과·그래프·진단·수치 표 |
| 상태줄 | 최소 높이 36 px | 모델 검증 상태·실행 시간·키보드 안내 |

라이브러리는 접을 수 있다. 창 너비가 761px 이상이고 중앙 가용 폭이 44rem 이상이면 좌우 배치를 유지하고, 더 좁거나 글자 크기를 확대하면 결과를 아래로 옮겨 가독성을 유지한다. 라이브러리·속성의 추가 접기와 키보드로 조절 가능한 폭 손잡이는 후속 설계 과제다.

```text
┌──────────── CalcWeave · 모델 이름 · 저장 상태 · 파일/도움말 ────────────┐
├────────── 선택 / 연결 / 확대        실행 방식       ▶ 실행 ──────────┤
│ 블록 검색   │ 루트 모델                     │ 계산 결과 │ 블록 속성 │
│ 입력       │                              │ 진단      │ 매개변수  │
│ 계산       │ [Constant 2] → [Gain 3]      │ 출력 6    │ 연결      │
│ 시간·상태   │                 ↓            │ 실행 정보 │ 지원 모드 │
│ 결과       │             [Display 6]      │ 그래프    │ 실행 설정 │
│            │                              │ 수치 표   │           │
├─────────────── 준비됨 · 실행 상태 · 키보드 안내 ──────────────────────┤
└──────────────────────────────────────────────────────────────────────┘
    250 px             558 px                  320 px       312 px
```

### 5.2 화면 크기에 따른 변화

| 가용 폭 | 동작 제안 | 보존하는 작업 |
| --- | --- | --- |
| 1150 px 초과 | 라이브러리·중앙 작업 공간·속성을 나란히 배치. 중앙 폭 44rem 이상이면 캔버스와 결과도 나란히 표시 | 전체 편집 |
| 761–1150 px | 라이브러리는 위쪽 가로 목록, 속성은 작업 공간 아래. 중앙 폭이 충분하면 캔버스와 결과는 나란히 표시 | 전체 편집·키보드 연결 |
| 중앙 폭 44rem 미만 | 캔버스 다음에 결과를 배치, 글자·입력을 축소하지 않음 | 도식 이동·결과와 진단 확인 |
| 760 px 이하 | 모바일에서는 세로 배치와 로컬 스크롤로 읽기 우선 | 복잡한 모바일 편집은 후속 검증 범위 |

작은 화면에서도 오류·현재 실행 상태·결과 최신성·저장 실패는 메뉴 안에 감추지 않는다. 창 크기를 변경해도 모델 좌표와 연결은 바뀌지 않는다. 반응형 재배치는 앱 패널에 적용하고 모델의 자동 정렬은 사용자 명령으로만 수행한다.

### 5.3 캔버스의 공간 규칙

현재 조작은 휠 버튼 드래그 이동, 빈 캔버스의 왼쪽 드래그로 푸른 사각형 범위 선택, 캔버스 포커스에서 Space로 도식 맞춤이다. 블럭의 왼쪽 드래그는 위치 편집에 사용한다. 입력·버튼·대화상자의 Space는 기본 동작을 유지한다. 최초 맞춤과 사용자 요청 맞춤은 읽기 크기를 보존하고 이후 일반 편집·실행은 viewport를 재설정하지 않는다.

- 기본 격자는 16 px, 정렬 스냅도 16 px로 제안한다. 정렬 안내선은 잠시 나타나고 계산 의미에 영향을 주지 않는다.
- 기본 블록은 최소 144 × 72 px, 본문이 짧은 산술 블록도 이름과 주요값을 읽을 수 있게 한다. 포트 수에 따라 높이를 늘린다.
- 기본 간격은 좌우 80 px, 상하 48 px를 자동 배치 시작값으로 사용한다. 사용자가 만든 배치를 실행할 때 바꾸지 않는다.
- 연결은 좌→우 방향을 기본으로 하고 입력은 왼쪽, 출력은 오른쪽에 배치한다. 피드백·제어 포트는 이름과 별도 위치로 구분한다.
- 선 교차는 연결을 뜻하지 않는다. 분기점에는 명시적인 점과 분기 설명을 둔다. 서로 다른 선의 교차에는 점을 넣지 않는다.
- 큰 모델에는 전체 보기, 선택에 맞추기, 검색 결과로 이동, 현재 서브모델 경로를 제공한다. 축소 시 블록 내부의 작은 텍스트를 읽기 어렵게 늘어놓기보다 이름과 지원 상태를 우선 표시한다.
- 자동 배치·전체 보기·패널 접기는 실행 취소 또는 이전 화면 위치 복원이 가능해야 한다. 구조 변경과 화면 이동은 이력에서 구분한다.

### 6.3 색각·움직임·그림자

- 상태는 색 + 아이콘 + 문구로 표시한다. 오류는 `! 오류`, 경고는 `△ 주의`, 완료는 `✓ 완료`처럼 텍스트가 있어야 한다.
- 선 종류는 의미가 실제로 다를 때만 패턴을 바꾼다. 일반 값 신호는 실선, 지원 단계에서 도입하는 제어·이벤트 경로는 이름과 별도 패턴을 함께 제공한다.
- 그래프의 여러 신호는 색 외에 실선/점선·마커·이름으로 구분하고, 범례에서 하나씩 선택할 수 있게 한다. 색각 시뮬레이션과 흑백 화면을 QA에 포함한다.
- 애니메이션은 기본 120–180 ms의 패널·선택 전환만 사용한다. 매 실행마다 신호를 계속 흐르게 하는 효과는 기본으로 넣지 않는다.
- 움직임 감소 설정에서는 전환과 신호 강조의 애니메이션을 끈다. 상태는 정적 텍스트로 계속 확인할 수 있게 한다.

## 7. 첫 성공 흐름과 예제

### M5에서 제공하는 고급 계산 경험

행렬은 scalar/vector로 자동 변환하지 않고 2D JSON 입력을 사용한다. LU의 L·U·P 포트와 선형 방정식의 A·B를 명시하며 특이·대칭/양의 정부호·조건 불량 오류를 계산 블럭에 연결한다. 2D Lookup의 행/열 기준점과 표 크기를 함께 설명하며 nearest 동률·previous·외삽의 차이를 속성에서 알려 준다. Fixed Quantize에는 비트 폭·소수 비트·부호·반올림·overflow를 노출하고 out/stored가 서로 다른 의미임을 설명한다. 일반 fixed-point 전파나 복소수 전체 지원으로 표시하지 않는다.

검정·차콜 다크와 회색 라이트, 16px 본문·14px 보조 글자, 캔버스/결과 좌우배치·작은 화면 세로 흐름을 보존한다. 실제 예제 수치를 계산하며 저장 재개방과 ZIP 코드로 같은 결과를 재현한다. UI 기능의 검증은 사용자 조사와 구분한다.

### M4에서 제공하는 실험 경험

작업 공간 탭은 도식·데이터·실험·대시보드·노트의 다섯 작업으로 나눈다. 도식과 결과의 좌우배치, 검정·차콜 다크 테마, 밝은 회색 라이트 테마, 본문 16px·보조 14px와 이름·핵심 값만 표시하는 블럭은 유지한다. 작은 화면에서는 패널과 필드를 순서대로 배치하고 표에는 내부 가로 스크롤을 제공한다.

데이터는 원본 앞 5행과 정리된 결과를 구분해서 보여준다. 타입·단위·결측·중복·정렬 옵션이 바뀌면 이전 미리보기를 무효화하고 다시 검증한 결과만 보관한다. 오류가 있는 파일은 프로젝트에 적용하지 않는다. 참조 중인 데이터를 삭제하려면 해당 재생 연결을 먼저 바꾸도록 안내한다.

서브시스템은 더블클릭으로 진입하고 경로를 따라 root로 돌아온다. 내부 계산 편집은 정의 버전을 올리며 다른 인스턴스는 명시적으로 갱신한다. 경계 포트는 내부에 숨은 상수로 오해하지 않도록 외부 연결 의미를 표시한다. 실행 중에는 확정된 root snapshot을 계속 계산한다.

실험 탭은 반복 횟수·진행·취소 상태와 완료 이력을 보여준다. 이력 복원은 당시 도식·데이터로 돌아가는 동작이며 단순 결과 조회와 구분한다. 비교는 시간 격자나 단위가 다르면 이유를 표시하고 자동 보간하지 않는다. Slider·Toggle의 변경은 다음 실행용 모델 편집이다. Display·Gauge·Scope에는 현재 또는 이전 snapshot의 결과를 표시하고 실행 중 값을 몰래 바꾸지 않는다. 노트와 설명 블럭은 일반 텍스트이며 계산 의미 hash를 바꾸지 않는다.

### M3에서 제공하는 실행 경험

연속 실행을 선택하면 RK4와 RK45, 초기·최소·최대 내부 간격을 표시한다. RK45에서 절대·상대 오차를 추가하고 사건 허용값·실행 횟수 상한은 펼침 영역에 둔다. 기본 시간 간격은 결과를 기록하는 격자이며 내부 적분 간격이 아니라는 설명을 입력 옆에 제공한다. 혼합 모델의 이산 기본 간격과 블럭의 정수 period/offset을 연결해 설명한다. 미완성 설정을 편집하는 동안 UI를 닫거나 값을 자동 보정하지 않고 실행 시 정확한 제약 진단을 반환한다.

예제는 RK45 감쇠, 2차 진동, 연속 step 응답, PID·필터 미분, crossing reset, Memory·고정 지연, 연속 샘플 hold와 제어된 솔버 실패다. 실패 예제는 잘못된 성공값 대신 마지막 유효 기록·중단 이유·시각을 확인하는 과제다. 예제 값·그래프를 사전 계산 화면으로 가장하지 않는다.

결과의 기본 흐름은 마지막 값 → 원시 그래프·전체 수치 표이며 solver 실행 기록은 수락·거절·미분 평가·사건 수와 승인 간격 범위를 표시한다. 사건 목록은 종류·시각·블럭 이름을 읽기 크기로 제공하고 전체 목록을 페이지로 접근한다. 실패·취소의 부분 기록은 완료 기록과 명시적으로 구분한다. 설정을 바꾸면 이전 결과를 유지하되 다시 계산 필요를 표시하며, 부분 결과를 expected-output 완료 fixture로 내려받지 않는다.

연속 ODE 상태·hold·사건의 현재 지원은 단위1 scalar이고 이산 영역의 boolean·벡터·2D는 유지된다. 연속→이산에는 Zero Order Hold, 다른 이산 rate 사이에는 Rate Transition을 안내한다. M9는 이산 limited integrator·PID clamping·제한 MIMO를 별도 계약으로 제공한다. 연속 limited integrator/anti-windup·연속 MIMO·복소수·강성 ODE·DAE와 임의 시각 발행 사건은 후속 범위다. 이 제한은 초보자 안내와 전문가용 solver 상세에서 같은 의미로 표시한다.

### 7.1 새 사용자의 3분 계산

첫 예제의 목표는 `2 × 3 = 6`이다. 모델링 개념을 설명하기 위해 불필요한 블록을 추가하지 않는다. 세 블록의 계산 결과 확인까지 3분은 개선 목표이며, 안내 예제·입력 변경·백업을 포함하는 M1 완료 게이트는 로드맵의 15분 과제로 평가한다.

1. 시작 화면에서 `첫 계산 만들기`를 선택한다. 계정 생성이나 외부 파일 설치를 요구하지 않는다.
2. 짧은 안내가 `값 · Constant` 블록을 추가하도록 한다. 블록 안의 값 `2`를 확인한다.
3. 검색으로 `배율 · Gain`을 찾고 `3`을 입력한다. 검색 결과의 설명은 “입력에 정해진 값을 곱합니다”로 한다.
4. 출력 포트→입력 포트를 클릭하거나 연결 버튼으로 두 블록을 연결한다. 연결 가능한 포트가 강조된다.
5. `값 표시`를 추가·연결하고 `계산하기`를 누른다. 결과 패널에 `6`과 입력 조건을 표시한다.
6. 값을 `4`로 바꾸면 이전 `6` 옆에 `다시 계산 필요`가 즉시 나타난다. 다시 실행하면 `12`가 나타난다.
7. `모델 파일 다운로드`로 휴대용 백업을 만들 수 있음을 안내하고, 브라우저 저장과 파일의 차이를 설명한다.

안내는 건너뛸 수 있고 모델은 일반 모델과 동일하게 편집할 수 있어야 한다. 안내 도중 취소해도 만든 블록을 지우지 않는다. 예제 실행 결과를 미리 렌더링한 데모 화면을 실제 엔진 실행 결과처럼 표시하지 않는다.

### 7.2 빈 상태와 실패 상태

| 상황 | 주 안내 | 다음 행동 |
| --- | --- | --- |
| 빈 모델 | `입력, 계산, 결과 블록을 연결해 첫 계산을 만들어 보세요.` | 첫 계산·예제 열기·블록 검색 |
| 결과가 아직 없음 | `아직 계산하지 않았습니다.` | 계산하기 또는 차단 오류로 이동 |
| 아무 출력도 선택되지 않음 | `계산할 결과가 지정되지 않았습니다.` | 결과 블록 추가 또는 지원되는 출력 선택 |
| 라이브러리 검색 결과 없음 | `이 이름의 블록을 찾지 못했습니다.` | 기능 키워드·전체 목록·지원 예정 확인 |
| 로컬 저장 실패 | `이 브라우저에 저장하지 못했습니다. 모델 파일을 다운로드해 보관하세요.` | 재시도·모델 다운로드 |
| 가져오기 실패 | `파일을 읽지 못했습니다. 14번째 행의 값 형식을 확인하세요.` | 오류 행 보기·설정 수정·다른 파일 선택 |

### 7.3 단계별 기본 예제 모델

| 예제 | 학습 목표 | 핵심 블록·화면 | 검증 기준 | 단계 |
| --- | --- | --- | --- | --- |
| 첫 배율 계산 | 입력→변환→출력 | Constant → Gain → 값 표시 | `2 × 3 = 6`, 매개변수 변경 후 최신성 표시 | M1 |
| 두 벡터의 내적 | 스칼라·벡터 형상 차이 | 벡터 입력 → Dot Product → 값 표시 | 알려진 작은 벡터로 계산·형상 오류 모두 확인 | M1 범위가 허용할 때 |
| 이전 값과 차이 | 이산 상태와 초기값 | 데이터/파형 → Unit Delay·Subtract → 그래프 | 첫 샘플의 초기값과 다음 샘플의 의미 표시 | M2 |
| 입력을 누적하기 | 이산 적분과 시간 간격 | Step → Discrete-Time Integrator → 그래프 | 시간 간격·초기값을 바꾸고 설정에 따라 재실행 | M2 |
| 1차 지연 응답 | 연속 시스템과 수치해 | Step → Transfer Fcn → 그래프 | 기술 사양의 해석해·오차 기준과 비교 | M3 |
| 표 기반 변환 | 데이터 열·단위·보간 | 데이터 → 1-D Lookup Table → 표/그래프 | 정해진 점·경계 처리·잘못된 입력 예제 | M4 |
| 재사용 서브모델 | 입출력 계약과 계층 | 입력 → 서브모델 → 출력 | 내부 모델 편집과 호출 모델의 최신성 연결 | M4 |
| 이상값 감지 | 실행 중 검증과 진단 | 입력 → 범위 확인 → 결과 | 실패한 샘플과 원인 블록으로 이동 | 해당 검증 블록 지원 단계 |

예제에는 목적, 예상 결과, 가정, 바꿔 볼 매개변수, 현재 실행·export 지원을 포함한다. 데이터는 합성 데이터를 기본으로 사용한다. 미지원 블록으로 구성된 예제는 실행 가능한 예제로 공개하지 않는다.

## 8. 블록·포트·연결 상호작용

### 8.1 블록의 정보 계층

```text
┌──────────────────┐
│       Gain       │  영어 종류 이름 하나
○        3         ○  핵심 숫자 하나
└──────────────────┘
```

M0 캔버스는 영어 종류 이름과 핵심 숫자만 표시한다. Constant·Input·Gain은 설정값, Unit Delay·Integrator는 초기값, Display는 현재 모델의 계산 결과를 표시한다. Display의 결과가 없거나 오래되었으면 `—`로 표시한다. 숫자 파라미터가 없는 Sum·Product는 이름만 표시하며 값을 창작하지 않는다. 아이콘·한영 이름 중복·파라미터 제목·장식 수식·왼쪽 세로 마킹을 추가하지 않고 카테고리는 절제된 테두리 색으로 구분한다.

사용자가 작성한 label과 내부 ID는 유지한다. label을 `매출 증폭`으로 바꿔도 캔버스의 종류 이름은 `Gain`이며 속성 패널·모델 목록·툴팁·접근 가능한 이름에서 사용자 label을 확인한다. 라이브러리와 속성 패널은 `배율 · Gain`처럼 한국어 설명과 영문 정식명을 함께 제공한다. 포트의 의미·연결 선택·지원 모드·수치 설정은 속성 패널에서 읽고 조작할 수 있다. 오류는 진단과 `!`로 표시해 색 이외의 정보를 유지한다. 자세한 표시 계약은 [SANE 화면 수정 기록](04-sane-design-revision.md)에 있다.

선택 시 오른쪽 패널은 `기본값 / 입출력 / 설명 / 지원 / 고급`의 순서로 보여 준다. 타입·형상·단위·샘플시간이 추론된 값인지 사용자가 고정한 값인지 구분한다. 추론에 실패한 것을 “자동”이라는 정상 상태로 덮지 않는다.

### 8.2 포트와 연결 계약

포트 상세는 `이름, 방향, 자료형, 형상, 단위, 실행/시간 의미`를 기술 사양에서 받은 값으로 표시한다. 정적 계산의 값 연결과 시간 신호 연결을 같은 표시로 오인하지 않게 현재 실행 방식을 항상 볼 수 있게 한다.

| 항목 | 요약 표시 예 | 상세·오류 원칙 |
| --- | --- | --- |
| 자료형 | `실수`, `불리언`, `문자열` | 내부 타입명을 상세에서 확인. 허용되지 않는 자동 변환 금지 |
| 형상 | `스칼라`, `벡터[3]`, `행렬[2×3]` | 행·열 방향과 요소별/행렬 연산을 분리 |
| 단위 | `m`, `s`, `m/s`, `단위 없음`, `미지정` | 미지정과 무차원은 구분. 일치하지 않는 단위를 조용히 무시하지 않음 |
| 시간 의미 | `정적`, `Ts = 0.01 s`, `연속` | 이산/연속 또는 샘플시간 경계를 명시 |
| 추론 상태 | `상위 입력에서 결정`, `수동 지정`, `미확정` | 상세에 결정 근거와 원인 입력 표시 |

M1은 기술 백서에 따라 단위 메타정보와 합산·비교의 기본 호환 검사를 시작 범위로 한다. 완전한 차원 대수·파생 단위·변환은 M4에서 확장한다. 구현 단계에서 검증하지 않는 항목은 `이 단위 조건은 현재 검증하지 않음`을 명시한다. 화면에 단위를 표시하는 것만으로 단위 안전성을 보장하지 않는다. 동일 차원의 변환도 실제 변환 규칙을 보여 주고 사용자가 승인한 명시적 변환 블록을 사용한다.

### 8.3 연결 방식

1. 출력 포트를 선택하면 적합한 입력 후보와 연결 안내가 나타난다.
2. 입력 포트를 선택하면 연결을 만든다. 드래그 연결도 같은 동작의 대체 수단으로 제공한다.
3. 방향이 맞지 않거나 타입이 다르면 연결 미리보기 옆에 이유를 표시하고 모델에는 반영하지 않는다.
4. 기존 입력 연결을 교체할 때 바뀔 선을 미리 표시한다. 한 입력의 동시 연결 수는 엔진 계약을 따른다.
5. 빈 공간에서 취소하거나 Esc를 누르면 시작 전 상태로 돌아간다. 연결 중 캔버스 이동으로 상태가 사라지지 않는다.
6. 선을 선택하면 `출발 → 도착`, 타입·단위·최근 값 또는 결과의 최신성을 볼 수 있다. 최신 값이 없으면 값이 있는 것처럼 표시하지 않는다.

키보드·스크린리더 사용자를 위해 속성 패널의 `입력 연결` 메뉴로 출발 블록/포트를 선택하는 방식도 제공한다. 정확한 화면 좌표나 선의 색을 이해해야만 연결할 수 있는 UI를 만들지 않는다.

### 8.4 오류의 위치와 문구

| 문제 | 핵심 문구 예 | 작업 제공 |
| --- | --- | --- |
| 필수 입력 없음 | `“더하기”의 두 번째 입력이 연결되지 않았습니다.` | 입력 포트로 이동·연결하기 |
| 형상 불일치 | `행렬 곱을 계산할 수 없습니다. 2×3과 2×2가 연결되어 있습니다. 왼쪽 열 수 3과 오른쪽 행 수 2가 같아야 합니다.` | 두 입력 확인·연산 방식 설명 |
| 단위 불일치 | `더하기의 입력 단위가 m와 s입니다. 같은 차원의 값이 필요합니다.` | 원본 입력 확인. 불가능한 변환 추천 금지 |
| 타입 불일치 | `문자열을 수치 입력에 연결할 수 없습니다.` | 지원되는 수치 변환과 변환 실패 설명 |
| 대수 루프 | `현재 지원 방식에서 이 순환 연결을 계산할 수 없습니다.` | 관련 블록 경로 강조·상태가 필요한지 설명. 의미가 바뀌는 지연을 자동 삽입하지 않음 |
| 미지원 실행 방식 | `이산 지연 블록은 현재 정적 계산 방식에서 실행할 수 없습니다.` | 지원 방식 설명·변경 영향 검토 |
| 시간 간격 부적합 | `시간 간격은 0보다 큰 유한한 값이어야 합니다.` | 해당 설정으로 이동 |
| 실행 중 비유한 값 | `나눗셈의 출력이 유한한 수가 아닙니다. t = …에서 분모를 확인하세요.` | 원인 입력·시점·이전 유효 결과 확인 |

오류 목록은 심각도, 위치, 문제 설명, 수정 행동 순으로 구성한다. 실행을 막는 오류와 실행 가능한 주의사항을 별도 개수로 표시한다. 오류를 확인했다는 행동으로 실제 검증 오류가 해제되면 안 된다.

## 9. 매개변수 입력과 모델 변경

- 숫자 입력은 초깃값·허용 범위·단위·예제를 함께 보여 준다. 빈 입력, `NaN`, 무한대, 잘못된 지수 표현 등은 해당 블록의 계약에 따라 검증한다.
- v0.1 숫자 표기는 소수점 `.`과 과학적 표기 `1e-3`를 기본으로 제안한다. 쉼표를 천 단위 구분자와 벡터 구분자 양쪽 의미로 조용히 해석하지 않는다. UI 언어와 입력 문법을 도움말에서 구분한다.
- 벡터·행렬 입력은 작은 표 편집기와 명시적 배열 입력을 제공한다. 파서가 허용한 문법을 표시하고 임의 JavaScript 실행 필드로 만들지 않는다.
- 필드 편집 중의 임시 문자열과 모델에 적용된 값을 구분한다. Enter·포커스 이동 시 유효값을 적용하고 Esc로 취소한다. 잘못된 입력은 모델에 저장하지 않고 필드 옆에 오류를 유지한다.
- 여러 설정을 함께 바꿔야 유효해지는 패널에는 `적용 / 취소`를 둔다. 도식·실행 조건이 잠시 불완전한 상태로 바뀌는 일을 피한다.
- 유효한 계산 매개변수 변경은 결과를 즉시 `다시 실행 필요`로 표시한다. 불완전한 입력 상태에서 자동 실행하지 않는다.
- 실행 방식 변경은 영향을 받는 블록·사라지는 옵션·새로 필요한 설정을 먼저 보여 준다. 오류가 있는 모델도 편집·백업할 수 있게 하고 실행만 차단한다.
- 삭제·연결 교체·매개변수 변경·붙여넣기는 실행 취소 대상으로 한다. 다른 모델·다른 브라우저 세션의 undo까지 보장한다고 표시하지 않는다.
- 고급 사용자의 식 입력도 기술 백서의 제한된 표현식 범위를 따른다. 지원 함수·입력·결과 타입·오류 위치를 표시하고, 일반 코드를 붙여 넣으면 실행될 것이라는 기대를 만들지 않는다.

## 10. 실행 상태와 결과의 최신성

### 10.1 서로 다른 상태를 분리

| 상태 축 | 값의 예 | 표시 위치 |
| --- | --- | --- |
| 모델 유효성 | 편집 중, 검증 필요, 실행 가능, 오류 있음 | 도구줄·진단 |
| 실행 상태 | 준비, 검증 중, 실행 중, 일시정지, 완료, 중단, 실패 | 실행 버튼 옆과 결과 헤더 |
| 결과 최신성 | 결과 없음, 현재 모델과 일치, 모델 변경됨, 데이터 변경됨, 일부 결과 | 결과 헤더·그래프·다운로드 |
| 저장 상태 | 저장 중, 브라우저에 저장됨, 저장 실패, 파일 다운로드 시각 | 앱 헤더·파일 메뉴 |

실행 완료·저장 완료가 결과 최신성을 뜻하지 않으며, 브라우저 저장 완료가 외부 백업을 뜻하지 않는다.

### 10.2 실행 컨트롤

| 실행 방식 | 기본 버튼 이름 | 기본 설정 | 상세 설정 |
| --- | --- | --- | --- |
| 정적 계산 | `계산하기` | 계산할 출력 | 타입·형상·계산 제한 |
| 이산 시뮬레이션 | `시뮬레이션 실행` | 시작·종료 시간, 시간 간격 | 초기값·시드·샘플시간·기록 간격 |
| 연속 시뮬레이션 | `시뮬레이션 실행` | 시작·종료 시간, 솔버 이름 | 허용오차·최대 스텝·지원 이벤트 처리 |

실행은 **시작 시점의 모델·입력·설정 스냅샷**을 대상으로 한다. 실행 중 편집을 허용하는 단계에서는 그 사실을 결과 헤더에 표시하고 결과를 현재 모델에 잘못 붙이지 않는다. 초기 구현에서 편집을 잠그는 경우 잠긴 이유와 정지 방법을 명확하게 보여 준다.

정지는 응답 가능한 주요 버튼으로 유지한다. 정지 요청에 대한 UI 응답은 1초 이내를 초기 검증 목표로 두되, 실제 작업 취소 완료의 의미와 최악 지연은 기술 스파이크에서 확인한다. 중단 후 부분 결과를 보존하는 기능이 있으면 `중단됨 · 부분 결과`와 마지막 완료 시각을 표시한다. 부분 결과와 정상 완료 결과를 같은 완료 색이나 같은 파일 이름으로 내보내지 않는다.

일시정지·단일 스텝은 M2의 실행 계약이 검증된 후 제공한다. 해당 기능이 없는 단계에서 눌리지 않는 아이콘을 주 도구줄에 계속 배치하지 않는다. 시간 진행률이 계산 가능한 경우에만 진행률을 표시하고, 준비·검증·적응형 계산에서 근거 없는 남은 시간 추정을 제공하지 않는다.

### 10.3 최신성과 결과 버전

- 결과에는 모델의 계산 의미 버전, 블록 카탈로그·엔진 버전, 실행 설정, 입력 데이터 버전 또는 지문, 난수 시드, 실행 시각을 연결한다.
- 값·연결·블록 종류·형상·단위 의미·실행 설정·입력 데이터 변경은 해당 결과를 오래된 결과로 만든다. 블록 좌표·확대율·주석의 표현만 바뀌면 수치 결과를 다시 계산할 필요는 없다.
- 표시 단위 변경이 계산 변환을 포함하는지 단순 보기 변경인지 기술 계약에 따라 판단한다. UI가 임의로 버전 무효화 기준을 결정하지 않는다.
- 오래된 결과는 삭제하지 않고 `이 결과는 모델 v8에서 계산되었습니다. 현재 모델은 v9입니다.`라고 표시한다. 재실행·해당 버전 보기·기록 보존을 제공한다.
- 입력 파일이 같은 이름으로 교체되었어도 다른 데이터이면 버전이 바뀐다. 파일명만으로 최신성을 판단하지 않는다.
- 반복 실행은 같은 입력·설정이면 비교할 수 있게 한다. 수치·난수 결과가 동일하다는 약속은 기술 사양의 재현 범위에 한정한다.

### 10.4 결과 읽기

| 결과 유형 | 기본 표시 | 상세 행동 |
| --- | --- | --- |
| 스칼라 | 값·단위·출력 이름 | 전체 정밀도 보기·복사·입력 경로 보기 |
| 벡터·행렬 | 크기와 표, 큰 값은 제한된 미리보기 | 원본 값 다운로드·행/열 탐색 |
| 시간 신호 | 시간 그래프·신호 범례 | 특정 시점 값·축 범위·표 보기·신호 선택 |
| 여러 출력 | 이름·타입·상태 목록 | 탭·비교·관심 출력 고정 |
| 검증 실패 | 실패 조건·블록·시점/행 | 원인 위치와 이전 유효 구간 이동 |

화면 표시 반올림과 실제 저장값을 구분한다. `약 0.333333`처럼 요약값과 전체 정밀도 값의 관계를 알려 준다. 그래프가 점을 줄여 보여 주면 `표시용 축약: 전체 N개 중 M개`를 표시하고 원본 다운로드는 실제 보존된 데이터 범위를 따른다. `NaN`·무한대·누락값을 임의로 0으로 바꾸지 않는다.

### 10.5 대시보드와 실행 중 조작

M4의 기본 대시보드 조작은 매개변수를 변경하고 **다음 실행에 적용**한다. 이미 시작한 실행의 입력 스냅샷은 바꾸지 않는다. 실행 중 조작 시 `다음 실행에 적용됨`과 현재 결과의 조건을 함께 보여 준다.

실행 중 조절 가능한 기능을 이후 제공하려면 별도 검증된 capability로 공개한다. 어떤 매개변수가 조절 가능한지, 값이 적용되는 tick·시각, 이벤트 순서, 변경 로그를 기록한다. 결과의 run manifest는 시작 스냅샷과 조작 로그를 함께 참조해야 하고, 재현 실행에서는 같은 로그를 입력할 수 있어야 한다. 단순히 슬라이더가 있다는 이유만으로 현재 계산의 파라미터를 조용히 바꾸지 않는다.

## 11. 저장·백업·데이터 관리

### 11.1 브라우저 저장과 휴대용 백업

| 기능 | 사용자에게 하는 약속 | 하지 않는 약속 |
| --- | --- | --- |
| 브라우저 자동 저장 | 이 브라우저의 저장 공간에 모델을 보관하고 저장 성공·실패를 표시 | 브라우저 초기화·저장소 정리·다른 기기 이동 후 보존 |
| 모델 파일 다운로드 | 지원 스키마의 모델을 사용자가 선택한 파일로 보관 | 모든 외부 데이터·모든 결과가 항상 포함됨 |
| 데이터 포함 백업 | 포함할 데이터·용량·결과 범위를 선택하고 구성 목록 제공 | 개인·비밀 데이터가 없는 안전한 공유 파일이라는 자동 보증 |
| 클라우드 저장, 선택 범위 | 제공 단계에서 저장 위치·동기화·충돌 상태를 설명 | 아직 구현하지 않은 협업·무손실 자동 병합 |

브라우저 저장소는 저장 한도와 데이터 축출 정책의 영향을 받을 수 있으므로 휴대용 백업과 구분한다. [MDN의 저장 한도·축출 설명](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)을 근거로 보존을 보장하는 문구를 피한다.

자동 저장은 유효한 편집이 완료된 후 묶어서 수행하고, 잦은 키 입력마다 저장 토스트를 띄우지 않는다. `저장 중`→`이 브라우저에 저장됨 · 14:32`가 조용히 갱신된다. 저장 실패는 계속 보이는 상태와 다운로드 행동으로 알려 준다.

다른 브라우저 탭에서 같은 모델의 저장 버전이 바뀌면 현재 편집을 조용히 덮어쓰지 않는다. 충돌을 알리고 현재 편집을 복사본으로 보관하거나 저장된 버전을 새로 여는 행동을 제공한다. 저장 성공 표시는 실제 저장 완료 이후에만 갱신한다.

파일 메뉴의 기본 이름은 `모델 파일 다운로드`다. “저장” 하나로 자동 저장·파일·클라우드를 모두 표현하지 않는다. 모델 백업에는 스키마 버전·필요한 블록과 실행 지원·포함 데이터 여부를 기록하고, 다시 열 때 지원하지 않는 버전·누락 데이터의 복구 안내를 제공한다.

휴대용 모델 파일은 기술 백서에 맞춰 `*.cw.json`을 제안한다. M4의 모델·데이터 묶음은 `*.cwpack` 후보를 사용하되 구성·압축·크기 제한은 기술 사양에서 확정한다. 브라우저와 로컬 파일 간 자동 동기화를 제공하지 않는다면 그 사실을 파일 메뉴에 명확히 표시한다.

### 11.2 데이터 가져오기 흐름

1. 사용자가 파일을 선택한다. 파일이 외부 서버로 전송되는지 로컬에서 처리되는지 **선택 전에** 현재 기능 기준으로 표시한다.
2. 크기·형식·파싱 범위를 확인하고, 지원 한도를 넘으면 모델을 변경하기 전에 거절한다. 한도 수치는 기술 스파이크 후 같은 카탈로그에서 읽는다.
3. 제한된 행 미리보기를 보여 주고 구분자·인코딩·헤더·누락값을 확인한다. 자동 추론 결과는 수정할 수 있다.
4. 열별 이름·타입·단위를 지정한다. 시간 신호는 시간 열, 시간 단위, 정렬·중복 시각·보간 규칙을 지정한다.
5. 숫자형 시간은 모델 시간 단위와 매핑한다. 날짜·시각 입력을 지원하면 원본 시간대와 표시 시간대를 명시하고 브라우저 로케일로 조용히 바꾸지 않는다.
6. 오류 행·값의 목록과 영향 행 수를 보여 준다. 실패한 값을 0으로 바꾸거나 행을 조용히 삭제하지 않는다.
7. 확인 후 데이터 버전을 만들고 입력 블록에 연결한다. 재가져오기 시 영향받는 모델·결과를 알려 준다.

데이터의 원본, 사용자 변환, 계산 결과는 각각 이름과 버전을 갖는다. 원본을 덮어쓰는 편집을 기본으로 하지 않는다. 데이터 탭에는 사용 중인 모델·열·용량·포함 백업 여부·삭제 영향을 보여 준다.

### 11.3 데이터 내보내기와 공유

- CSV 등 결과 파일은 출력 이름·단위·시간 열·누락값 표현·정밀도를 미리 보여 준다. 화면 반올림과 export 반올림을 따로 설정한다.
- 파일명 기본값은 모델명·실행 ID·결과 상태를 포함한다. 오래된 결과·부분 결과는 파일과 메타정보에서 표시한다.
- 사용자가 공유용 모델 파일을 만들 때 데이터·결과·주석의 포함 목록을 제공한다. 외부 파일 경로·개인 데이터·비밀 값을 자동으로 안전하다고 판단하지 않는다.
- 텍스트 셀의 스프레드시트 수식 해석 가능성은 export 구현에서 검증한다. 보호 처리가 원문을 바꾸면 선택한 처리를 미리보기와 export 메타정보에 표시한다.
- 삭제는 모델 참조와 결과의 영향을 표시하고, 복구 가능 범위를 설명한다. 장기간 클라우드 보존 정책을 로컬 MVP의 약속으로 혼용하지 않는다.

## 12. 코드 export 경험

### 12.1 모델 실행과 export 지원을 분리

블록 설명과 export 화면은 `화면 실행 지원`과 `선택한 언어의 export 지원`을 별도 표시한다. 화면에서 시뮬레이션된 모델이라고 모든 솔버·대시보드·외부 코드가 TypeScript로 변환되는 것은 아니다. 처음에는 M2에서 검증된 부분집합만 활성화한다.

export는 현재 모델의 검증된 스냅샷을 대상으로 한다. 결과 데이터를 함께 넣는 선택이 있는 경우 그 데이터의 실행 버전도 별도로 표시한다. 코드를 생성하는 데 이전 결과가 반드시 필요한 것처럼 안내하지 않는다.

### 12.2 내보내기 단계

| 단계 | 화면 내용 | 완료 조건 |
| --- | --- | --- |
| 1. 목표 선택 | TypeScript 등 실제 제공 언어, 함수/실행 패키지 등 제공 형식 | 지원되는 목표를 선택 |
| 2. 지원 검사 | 지원 블록·불가 블록·설정·외부 데이터·필요한 런타임 | 계산 의미의 미지원 부분이 없거나 사용자가 명확한 별도 모델로 수정 |
| 3. 입출력 계약 | 입력 이름·자료형·형상·단위, 상태 초기화·시간 의미, 출력 | 모델 계약과 코드 계약 확인 |
| 4. 미리보기 | 생성 파일 목록·코드·README·동봉 런타임·실행 조건·제한 | 버전과 의존성을 볼 수 있음 |
| 5. 다운로드 | 실제 패키지·모델 매핑·검증 결과 | 생성·검증 상태가 파일 구성과 일치 |

불가 블록을 무시하고 일부 코드만 다운로드하는 흐름을 기본으로 하지 않는다. 예를 들어 그래프 표시가 코드 계산에 필요하지 않으면 “결과 표시 UI 제외, 수치 출력은 유지”라는 계약을 보여 준다. 계산 블록을 제거해야 한다면 원본 모델과 다른 명시적인 export 모델로 만들고 사용자에게 변경을 확인시킨다.

### 12.3 코드 이해를 돕는 내용

- 생성 코드의 입출력 인터페이스와 실행 예제를 보여 준다. 코드 경험이 없는 사용자는 파일 다운로드만으로 무엇을 얻는지 알 수 있어야 한다.
- 블록 선택↔코드 구간의 매핑을 제공한다. 이름을 그대로 실행 식별자로 쓰지 않고, 읽기 좋은 이름과 안정된 블록 ID를 연결한다.
- 코드를 미리보기에서 수정하더라도 모델에 자동 반영되지 않는다는 점을 명시한다. 양방향 편집은 별도 제품 기능이 검증되기 전에는 약속하지 않는다.
- `생성됨`, `검증 통과`, `외부 실행 미검증`을 구분한다. 브라우저 미리보기에서 읽을 수 있다는 사실만으로 실행 검증 완료 표시를 하지 않는다.
- M2의 기본 TypeScript export는 필요한 CalcWeave 실행 런타임을 함께 묶는 방향으로 설계한다. 실행에 Node.js·브라우저 등 어떤 호스트 환경이 필요한지는 파일 목록과 README에 명시한다. CalcWeave 자체의 무설치 웹 경험과 export 코드의 실행 환경을 혼동하지 않는다.
- C/C++·Python·WASM 등 확장 목표는 M7에서 지원표와 검증을 추가한 후 공개한다. 초기 언어 선택 메뉴에는 작동하지 않는 목표를 기본 옵션처럼 넣지 않는다.

## 13. 키보드·스크린리더·터치

### 13.1 접근 가능한 대체 구조

캔버스 외에 모델을 `블록 목록 → 입력 연결 → 출력 연결 → 설정`으로 읽고 편집하는 구조를 제공한다. 이는 키보드 대체 UI인 동시에 큰 모델 탐색에 사용한다. 도식 좌표만으로 계산 구조를 전달하지 않는다.

- 주요 영역에는 이름을 붙이고, 영역 간 이동·현재 위치를 확인할 수 있게 한다.
- 블록 접근 가능한 이름의 예: `배율, Gain, gain 3, 입력 1개, 출력 1개, 오류 없음`.
- 포트 접근 가능한 이름의 예: `배율의 입력, 실수 스칼라, 단위 없음, 상수와 연결됨`.
- 선택·포커스·연결 시작은 다른 상태다. 포커스가 옮겨갔다고 블록을 편집하거나 선을 교체하지 않는다.
- 실행 시작·완료·오류·저장 실패는 적절한 알림으로 전달한다. 실행 중 매 샘플을 읽어 주지 않는다.
- 대화상자는 제목·초기 포커스·Esc 닫기·원래 포커스 복원을 갖추고, 빠져나올 수 없는 포커스 함정을 만들지 않는다.
- 200% 화면 확대와 긴 한국어 이름에서도 핵심 작업과 오류 문구에 접근할 수 있어야 한다. 가로 도식 자체는 이동 가능하되 앱 메뉴·속성은 불필요한 가로 스크롤을 줄인다.

### 13.2 단축키 제안

브라우저·OS의 기본 단축키와 충돌을 검증한 뒤 확정한다. 아래 키는 편집기 영역에 포커스가 있을 때만 적용하며 텍스트 입력·한글 조합 중에는 입력을 우선한다. macOS에서는 플랫폼 표기에 맞는 키를 보여 준다.

| 행동 | 제안 키 | 대체 UI |
| --- | --- | --- |
| 블록 검색 | `/` | 라이브러리 검색 버튼 |
| 실행 | Ctrl + Enter | 이름 있는 실행 버튼 |
| 취소·연결 종료 | Esc | 취소 버튼 |
| 실행 취소 / 다시 실행 | Ctrl + Z / Ctrl + Shift + Z | 편집 메뉴 |
| 복사 / 붙여넣기 | Ctrl + C / Ctrl + V | 문맥 메뉴. 입력 필드에서는 텍스트 편집 우선 |
| 선택 삭제 | Delete | 삭제 메뉴·버튼 |
| 블록 선택·포트 선택 | 목록 탐색 후 Enter | 접근 가능한 모델 목록 |
| 위치 이동 | 방향키 | 속성의 위치 또는 정렬 명령 |
| 캔버스 이동 | 휠 버튼을 누르고 드래그 | 도식 맞추기 버튼으로 전체 보기 |
| 영역 선택 | 캔버스 빈 곳에서 왼쪽 버튼 드래그 | Shift+클릭·접근 가능한 모델 목록 |
| 도식 맞추기 | 캔버스에서 Space | 도식 맞추기 버튼 |

캔버스 이동·영역 선택·Space 맞춤은 2026-10-02 사용자 지정 동작으로 적용했다. 영역 선택은 양쪽 테마에서 푸른색 반투명 사각형과 테두리로 표시하며, 블록 자체를 왼쪽으로 드래그하는 위치 편집은 유지한다. Space는 캔버스 또는 블록에 포커스가 있을 때 한 번 실행한다. 입력 필드·버튼·대화상자·한글 조합·보조 키 조합은 기본 동작을 유지하고, 키를 누른 채 반복되는 맞춤은 막는다.

`Ctrl + S`를 지원할 경우 이름은 `지금 브라우저에 저장`으로 명확히 한다. 다운로드와 브라우저 저장을 같은 단축키로 혼동시키지 않는다. 단축키 도움말과 사용자 재지정은 후속 검증 범위로 둔다.

### 13.3 터치와 포인터

데스크톱 연결 포트의 보이는 점이 작아도 클릭 대상은 최소 24 × 24 px로 제안하며, 서로 다른 포트의 대상 영역이 겹치지 않게 한다. 터치 UI가 지원되는 단계에서는 주요 대상 44 × 44 px와 탭→탭 연결을 제공한다. 포인터 드래그를 대신하는 클릭 작업은 [WCAG 2.2의 드래그 대체 기준](https://www.w3.org/TR/WCAG22/#dragging-movements), 최소 목표 크기는 [해당 기준](https://www.w3.org/TR/WCAG22/#target-size-minimum)과 예외 조건을 검토한다.

M1은 데스크톱 포인터·키보드 편집을 기준으로 검증한다. 모바일에서는 읽기와 결과 확인을 우선한다. 핀치 확대·길게 눌러 문맥 메뉴·여러 손가락 제스처가 없으면 못 쓰는 편집 방식은 기본에 넣지 않는다. hover 도움말은 터치·키보드에서도 여는 별도 행동이 있어야 한다.

## 14. 언어·문구·도움말 규칙

- 초기 기본 UI는 한국어를 우선 제안하고, 영문 정식 블록명은 검색·도움말에서 유지한다. 영어 UI 확장은 같은 블록 ID와 번역 리소스를 사용한다.
- 제품 설명에서는 “블록”을 통일해 쓰고 검색에는 “블럭”도 별칭으로 허용한다.
- `Scope`는 `시간 그래프 · Scope`처럼 작업 목적을 먼저 보여 준다. `Source`, `Sink`, `Bus`, `Sample Time`은 한 줄 설명을 붙인다.
- 실행·내보내기·저장 동작은 구체적인 동사를 쓴다. `확인` 버튼만으로 데이터 변환·삭제·코드 생성을 실행하지 않는다.
- 오류는 사용자를 탓하지 않는다. 문제의 위치와 조건을 말하고 가능한 다음 행동을 알려 준다.
- 주의사항은 해당 매개변수 옆·실행 설정·export 지원 검사처럼 판단이 필요한 위치에 둔다. 매번 긴 경고 대화상자를 띄우지 않는다.
- 모델 주석·파일명·열 이름·오류의 원문은 안전한 텍스트로 표시한다. HTML이나 실행 코드로 해석하지 않는다.
- 숫자 출력에 쓰는 자릿수·단위·시간대는 결과 옵션에서 확인할 수 있다. 원본 데이터·계산값과 표시 형식을 구분한다.
- 도움말의 각 블록 문서는 `무엇을 함 → 작은 예제 → 입력/출력 → 주요값 → 오류 → 실행·export 지원 → 제한` 순으로 작성한다.

## 17. UX 검증 계획과 목표

아래 수치는 초기 제품 목표다. 실제 사용성 수치나 시장 검증 결과가 아니다. 한 번의 작은 시험으로 전체 사용자 집단에 효과가 검증되었다고 결론내리지 않는다.

### 17.1 검증 작업

| 작업 | 모집·방법 제안 | 성공 목표 | 중요한 실패 신호 |

| export 이해 | 지원 모델·미지원 모델 각 1개 | 생성·검증·외부 실행 조건을 구분 | 다운로드만 하면 독립 실행된다고 기대 |
| 키보드 작업 | 키보드만으로 검색·삽입·연결·설정·실행·진단 이동 | 핵심 작업 전부 완료, 포커스 함정 0건 | 캔버스에 진입 후 빠져나오지 못함 |

3분 개선 목표에는 참가자의 사전 설명을 최소화한 세 블록 작업을 사용하고 실제 타이머 시작·종료 조건을 기록한다. M1의 15분 게이트 과제는 예제·입력 변경·파일 저장을 포함해 별도로 평가한다. 첫 계산 자체와 파일 백업까지의 시간을 각각 측정해 어떤 단계가 어려운지 분리한다. 작은 표본의 비율은 개선 신호로 해석하고 M6에서 참가자와 과제를 확대한다.

### 17.2 접근성·성능 검증

- 키보드와 스크린리더로 핵심 모델 작성·실행·결과 읽기를 확인한다. 자동 접근성 검사만 통과했다고 완료 처리하지 않는다.
- 라이트/다크, 색각 시뮬레이션, 200% 확대, 한국어 긴 이름, 동작 감소 설정을 확인한다.
- M0에서 대표 브라우저·기기·100/500/1000개 블록 등 모델 규모의 시험 행렬을 정하고, 실제 지원 규모는 기술 스파이크로 확정한다. 이 수치는 출시 보장치가 아니다.
- UI 입력 반응, 확대·이동, 검증, 실행 취소·정지 반응, 그래프의 대량 결과 읽기를 각각 측정한다. 계산 실행 시간과 편집 반응 시간을 섞어 한 가지 “빠름”으로 보고하지 않는다.
- 성능 제한에 도달할 때는 모델을 손상시키지 않고 작업 한도·축소 방법·백업 행동을 제공한다.
- 사용성 시험은 합성 모델·데이터로 시작한다. 제품에 실제 분석 도구를 넣는 결정은 별도 개인정보·동의 검토와 수집 범위 설계 후 진행한다.
